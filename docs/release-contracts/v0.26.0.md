# v0.26.0 发布契约

## 发布范围

本版以 `0.25.0` 之后已合入 main 的运行时改造为新 Preview 里程碑，主扩展与 notifier 统一为 `0.26.0`。交付类似 tmux 的会话重新附着（直接导入终端当前状态）、退出完整性、有限缓存与消费节奏控制、已结束 Runtime 的轻量保存，以及 OSC 8 / 缩高状态恢复修复。新建执行默认采用当前平台原生实现；已有 live 会话保留原 Supervisor 与协议绑定。另更新 Markdown 渲染依赖，修复自动识别链接时部分长文本的阻塞问题。notifier 仅版本对齐。

本版不新增模板市场生产服务部署，不新增用户设置，也不改变 Preview 定位、扩展身份或 companion 安装关系。不承诺监督器/机器故障后的恢复、跨版本 journal 回退、固定总资源预算或旧操作系统兼容性。

## 用户 release notes

采用类似 tmux 的会话重新附着方式：Supervisor 持续持有原进程和权威终端模型，窗口/Webview 或 Pane Gallery 重建时直接导入当前状态，无需从历史输出逐条重放来重建画面。这个更直接的恢复路径消除了累计历史回放带来的耗时增长；恢复工作取决于当前保留状态的大小。

当前状态包含屏幕、配置范围内的 scrollback、光标和终端模式等必要上下文；scrollback 随状态导入，不是另行回放旧输出的阶段。导入后从同一输出位置继续消费新内容，已有页面尚未消费的内容仍按序收齐。实现沿用 xterm 状态导出/导入，不新增 tmux 依赖；会话和 Supervisor 必须仍存活，不承诺恒定恢复耗时。主动停止与自然退出分别表达。

**已结束的持久化 Runtime 重开不恢复终端正文，不自动 start/resume。** 节点、布局、启动配置和退出状态仍保存；provider 自己的会话文件和用户显式 Resume 独立保留。等待输入但进程存活的 Agent 不属于已结束。snapshot-only 不在这项历史保存规则的改动范围内。

升级前停止重要会话、另行保存所需输出并备份画布；已有配置继续沿用。旧 live 会话不自动迁移，不获得新协议保证。主扩展与 notifier 一起升级；回退需要重新验证工作区数据，优先后续 0.26.x 修复版。

## 已知限制

Supervisor 崩溃、执行机器重启或断电后，不保证原进程或终端历史恢复；强后端也不提供额外灾后保证。跨 Host 存活仍取决于持久化开关与后端，snapshot-only 不承诺跨 Host 存活。

运行资源随会话数、尺寸和 scrollback 增长，无固定总内存、磁盘硬配额或零导入延迟保证。启动/存储责任未结算时可能拒绝新建；原生资产缺失明确失败，不静默切回旧实现。旧协议历史无法补造完整性。

原生资产覆盖 Linux glibc、macOS、Windows x64/arm64，验证以现代系统为基线，不外推旧系统或 Linux musl。Windows Codex 节点内历史向上翻页限制保留。Restricted Mode 只有有限画布能力，Virtual Workspace 不支持。notifier 点击回跳和通知投递仍依赖本机权限与后端。

已声明的 90,000 行与真实 Agent 重载验收不代表任意输出、并发或全平台满 scrollback 保证；Fork 视觉边界、跨节点多指触控与真实 TUI resize 人工复核沿用既有 Preview 限制。
