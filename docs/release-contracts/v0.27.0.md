# v0.27.0 发布契约

## 发布范围

主扩展与 notifier 同步为 0.27.0，交付自 0.26.0 之后已合入 main 的执行可靠性改进与同 root 多窗口共享画布。范围包括 root 稳定归属、启动失败反馈与准入结算、旧历史清理和协议重连、本地 Agent / Terminal 生命周期、终端输入与 resize、路径拖放、文件链接与文件活动、恢复身份、执行提醒，以及持久化模式切换时的共享清理和接管。

本版还收口共享删除的处理中状态：删除期间锁定受影响节点交互，并在共享模式的同 root 窗口间同步。失联 Agent / Terminal 节点可在明确通信失效时移除；新 Supervisor 可在 Unix 上修复丢失的 socket 入口。后台停止无法确认时保留未确认记录并提示用户手动检查，不自动结束进程或清理记录。该修复不赋予已运行的旧 Supervisor 热更新能力。

保持公开 Preview、现有设置、扩展身份和安装关系。notifier 自身不增加投递后端、协议、点击回跳或语言行为。模板市场生产部署独立于插件发布；多设备、多用户与云同步不在范围内。

## 用户 release notes

开启 Runtime Persistence 时，同一执行环境、用户存储范围和 root 的画布结构会在多个窗口同步；共享删除移除各窗口节点投影，停止保留节点和退出状态。关闭持久化时，画布按当前工作区私有保存。模式修改在关闭或重载边界应用，不迁移私有/共享内容；模式切换可能舍弃另一种模式中的内容，请提前备份。未修改模式的普通关闭或重载继续保留共享会话。

删除进行时画布会显示处理中状态并锁定受影响交互，同 root 的共享窗口也会同步该状态。启动失败会显示底层原因，结束待启动态并保留安全重试/删除路径；修复启动期间尺寸协调、删除前输入收口、本地执行终态/保存/重载、路径拖放、逐行和换行文件链接、文件活动及执行提醒。snapshot-only 下因 Host 关闭中断且有可信恢复身份的 Agent 等待手动 Resume，重开页面不会自动恢复。

失联的 Agent / Terminal 节点可以从画布移除，新 Supervisor 可在 Unix 上修复丢失的 socket 入口。若无法确认旧后台进程已停止，VS Code 会提示用户手动检查；扩展保留未确认记录，不自动结束或清理该后台进程。

从 0.26.0 升级前停止重要会话、另行保存需要留存的输出并备份画布；主扩展与 notifier 建议一起升级。已结束持久化 Runtime 仍不恢复终端正文或自动执行；provider 自身会话文件与显式 Resume 独立保留。旧 live 会话不自动迁移到新协议；跨版本回退需要重新验证，优先后续 0.27.x 修复版。

## 已知限制

Supervisor 崩溃、执行机器重启或断电后不保证原进程和终端历史恢复。资源随会话数、尺寸和 scrollback 增长，无固定总内存/磁盘配额或零延迟承诺。旧 live 协议不获得新完整性保证，跨版本工作区/运行时数据回退不保证兼容；共享/私有模式切换会舍弃原模式内容，应事先备份。

无法确认停止的失联后台可能继续运行，用户需手动检查；扩展不会自动结束或清理这些进程。Unix socket 修复由新 Supervisor 获得原运行时独占后执行，已运行的旧 Supervisor 不会热更新获得该能力。

部分 VS Code 版本在连续快速重开时可能积压已关闭 Webview 的资源请求，延迟新画布加载。持续启动失败可能留下空白画布，当前没有专门的启动超时提示、自动重试或重建；较长测试等待不提供上述产品能力。

原生资产覆盖 Linux glibc、macOS、Windows x64/arm64，现代系统证据不外推旧系统或 Linux musl。Windows Codex 历史向上翻页限制保留；Restricted Mode 执行入口禁用，Virtual Workspace 不支持。共享画布真实 UI 证据限 Linux 单 root；四阶段接管有受控 Host/store 和独立 Supervisor 证据，不等同全平台、多 root 或 Remote SSH 接管 UI 验收。notifier 投递和点击回跳依赖本机权限与后端。

## 验证范围

用户报告近期连续两天试用未发现明显问题；具体构建、平台与场景范围未记录，因此只作为定性反馈，不代替发布验收。

本版使用 `docs/WORKFLOW.md` 与 `docs/design-docs/release-gate-redesign.md` 定义的完整发布任务图，不继承 0.26.0 的一次性验证例外。发布 PR 以最新 head 与目标分支生成的真实预合并 SHA 执行 `release-pr`；合入 main 后，最终 `publish/v0.27.0` 指向的 SHA 独立执行 `release-tag`。两次均由 Actions 的 `ci-validation.yml` 按该输入的 `scripts/gates/catalog.mjs` 冻结全部必跑任务、环境、预算与产物身份。

验证范围包括静态发布契约、全部登记回归与类型检查、Webview 功能与固定视觉、Marketplace 浏览器和 Host 场景、六目标原生资产加载与操作、全部标准 source-host / packaged-host 场景，以及 Linux、macOS、Windows 三个 x64 目标的原样双包安装。主扩展与 notifier 在 `package-clean` 的干净源码和锁定依赖中生成同批候选 VSIX；后续 packaged-host、原样安装与交付均消费原双包，校验输入、版本、摘要和回执，不重新打包。

正式验收须独立核对实际 Actions job / 工件来源、完整必跑集合和同批产物；发布 PR 的 `Verify release contract` 依赖该验收成功。少结果、取消、错输入、取证或清理失败均不算通过。`npm run release:preflight -- --version 0.27.0` 仅检查静态输入；本地 `npm run release:verify -- --version 0.27.0` 在隔离 checkout 运行同一任务图，但只输出 `acceptance: false`，缺少的外平台任务记为 `not-run`，不能替代正式跨平台验收。

重点核对启动/准入失败呈现、原执行终态和保存、删除前输入关闭、删除中的本地与跨 Host 反馈、失联节点移除和未确认提醒、Unix socket 原位修复、resize 后页面与原进程尺寸一致、旧会话重连和退役、真实新 Host/checkpoint、同 root 双窗口结构同步/切换、systemd 与 fallback 及 localhost SSH。Webview 全套保持原断言和截图基线；fake Agent 与 Linux 本机结果不代证真实 provider 或其他平台组合。

notifier 类型/source、companion 回跳、英中文 locale 与同批 notifier VSIX 的版本、README、安装依赖及 NLS/l10n 均纳入任务图。真实桌面点击与公开市场自动补齐按实际宿主/渠道检查，staged smoke 不代证系统权限或市场依赖安装。四项真实 TUI、最低宿主、arm64 原样安装、真实 systemd 与跨平台 / 多 root 接管的未覆盖边界沿既有设计保留，不由上述有限平台操作和安装验收扩张为支持承诺。
