# 画布外层控件侧栏化规格

当前状态：草案。本文档用于收口 `功能体验.md` 第 2 条，并定义“画布只保留底角必要控件，非空间控件迁到 VSCode 侧栏”的产品范围与验收口径。

## 1. 用户问题

当前画布已经去掉了右侧选中节点信息区，也把左下角遮挡问题修掉了，但整体仍然保留了左上角 hero 和右上角操作 panel。这比之前更克制，却仍然有四个明显问题：

- 固定 panel 继续占用画布本体，让空间化工作面带着 dashboard 感。
- 创建对象、恢复状态、更新时间和说明性文字大多不依赖节点空间关系，却仍然压在画布里。
- 当编辑器宽度较窄，或画布里同时存在多个运行窗口时，顶部固定 panel 会持续抢占可用空间。
- 用户缺少一个位于 VSCode 宿主层、可以稳定访问的极简全局入口，只能把很多“应该离开画布”的动作继续留在画布里。

## 2. 目标用户

本规格优先服务已经在 VSCode 中使用 DevSessionCanvas 画布进行多 Agent 协作的开发者。用户需要一张尽量干净的主工作面来理解节点、关系和整体进度，同时又需要一个不打断画布的轻量入口来完成全局动作。

## 3. 核心用户流程

1. 用户在 VSCode 中打开 Dev Session Canvas 的侧栏入口；本规格关注其中的 `概览` 与 `常用操作` 两个 section，`模板`、`节点`、`会话历史` 由各自规格约束。
2. 用户从 `常用操作` section 直接打开或重新定位画布，或触发“创建节点”“重置画板”“清空画板”。
3. 当文件功能开启时，用户在 `常用操作` section 里直接使用 `包含文件` / `排除文件` 输入框，而不是再弹出额外菜单；当文件功能关闭并 reload 后，这组入口不会继续显示为可用状态。
4. 用户回到画布后，画布顶部不再显示固定说明卡片或操作区，只保留节点本体和底角导航元素。
5. 当 workspace 未受信任、画布尚未打开或有执行型对象在运行时，用户仍能在 `概览` section 看到简短状态，并理解当前哪些动作可用、哪些动作会在点击后给出受限原因说明。

## 4. 在范围内

- 移除画布 Webview 中左上角与右上角的常驻说明/操作 panel。
- 画布内默认只保留两类常驻角落 UI：
  - 左下角：导航性质控件，例如缩放和回到全局视图。
  - 右下角：全局定位性质控件，例如 MiniMap。
- 默认提供一个 VSCode 侧栏承载面，作为以下能力的主入口：
  - 本规格管辖 `概览` + `常用操作` 两个 section；同一 Dev Session Canvas 侧栏容器还可以包含模板、节点列表与会话历史等其他 section，但它们的功能范围不由本文展开
  - `概览` 继续使用原生 TreeView 展示最小必要状态，例如 workspace trust、画布是否已打开、Runtime Persistence 状态、通知模式、文件功能状态、当前文件视图配置、节点总数，以及必要的执行状态摘要；其标题行尾部提供设置快捷入口，直接打开本扩展设置
  - `常用操作` 提供打开或定位画布、创建节点、重置画板、清空画板，并在文件功能开启时额外显示 `include` / `exclude` 输入框；其标题行尾部保留原生风格的快捷 icon，复用高频动作但不要求每个文字按钮都进入标题栏
- 在 `常用操作` section 中，直接以内嵌输入框承载 `包含文件` / `排除文件`：
  - 输入框默认直接显示当前 glob 值
  - 输入框在 sidebar 内就地编辑，而不是弹出单独菜单
  - 过滤只影响文件对象与自动边的显示投影，不修改 `fileReferences`
  - 当 `devSessionCanvas.files.enabled = false` 且已完成 reload 后，这组输入框隐藏或进入不可用态
- 当侧栏不可见时，上述动作仍可通过命令入口到达。
- 侧栏整体信息密度保持极简，不引入长段说明、教学大卡片或复制节点正文。

## 5. 不在范围内

- 在侧栏复刻选中节点详情、Agent/Terminal 连续输出、Note 正文或其他 richer metadata
- 用侧栏取代画布成为主要工作面
- 新增 dashboard 式信息墙、复杂 tab 编排或自绘 mini app
- 不在本规格中定义完整节点列表、关系图或 mini inspector；节点列表与会话历史入口由 `docs/product-specs/canvas-sidebar-node-and-session-lists.md` 约束
- 在本轮重新设计节点本体字段、执行会话窗口或对象关系模型
- 在 sidebar 内继续仿制 VSCode Search 视图的自定义输入框外观

## 6. 关键对象与状态

### 概览 section

- 画布状态：已打开、未打开
- workspace trust 状态
- Runtime Persistence 状态
- 通知模式
- 文件功能状态
- 当前文件节点类型与显示模式
- 当前节点总数
- 当前执行型对象的最小摘要，例如运行中数量或受限提示
- `Codex 命令` / `Claude Code 命令` 行点击后进入命令选择；如果当前执行宿主没有解析到对应 CLI，则在同一入口显示安装选项
- 标题行尾部的设置快捷入口

### 常用操作 section

- 打开或定位画布
- 创建节点
- 重置画板，即清空当前画布后套用当前默认模板
- 清空画板
- 重置画板与清空画板使用一致的破坏性按钮视觉，靠文案区分是否套用当前默认模板
- 打开、创建、清空等高频动作的快捷 icon 入口
- 文件功能开启时显示的 `包含文件`
- 文件功能开启时显示的 `排除文件`
- 输入框就地编辑与清空
- “只影响投影、不改权威状态”的过滤语义

### 画布 Webview

- 节点对象图
- 当前视口与相机状态
- 左下角导航控件
- 右下角全局定位控件
- 临时错误提示或短时反馈

### 共享动作

- 打开或定位画布
- 创建对象
- 重置画板
- 清空画板
- 在受限模式下保留执行型动作入口，但在点击时解释为什么当前不可用

## 7. 验收标准

- 用户打开画布后，左上角和右上角不再出现常驻 hero、统计卡片或创建/恢复 panel。
- 左下角只保留导航性质控件，右下角只保留全局定位性质控件；这两个区域都不承载长段说明文本。
- 用户可以从默认侧栏入口的 `常用操作` section 打开或定位画布，并完成创建节点、重置画板与清空画板。
- 用户可以从 `概览` section 标题行尾部直接打开 Dev Session Canvas 设置。
- 用户点击 `概览` 中的 `Codex 命令` / `Claude Code 命令` 时，如果当前执行宿主没有找到对应 CLI，会先看到 `安装 Codex` / `安装 Claude Code` 入口；选择后再进入 `命令行安装` 与 `安装 VS Code 插件` 两个二级选项。
- 用户选择 `命令行安装` 后，画布中新建并启动一个 Terminal 节点，自动输入并执行对应 CLI 安装命令；用户选择 `安装 VS Code 插件` 后，扩展打开对应 VS Code 插件安装页，由用户自己点击 Install。
- `常用操作` section 的标题行尾部存在一排 icon-only 快捷按钮，复用内容区里的高频动作，视觉上贴近 VSCode 原生 toolbar / action。
- 侧栏整体采用“概览原生 TreeView + 常用操作最小 WebviewView”的混合风格；Webview 只用于承载必须存在的 inline 输入框和高频动作，不发展成 dashboard。
- 当文件功能开启时，`包含文件` / `排除文件` 会直接显示在 `常用操作` section 中，并在 sidebar 内就地编辑，不再弹出单独编辑菜单；当文件功能关闭并 reload 后，这组入口不会继续显示为可用状态。
- 侧栏不展示选中节点的重复信息，也不复制节点正文、会话 transcript 或连续输出。
- 当 workspace 未受信任时，侧栏与 `创建节点` 命令仍保留 `Agent` / `Terminal` / `Note` 三类创建入口；若用户点击当前不可用的执行型入口，扩展会弹出明确说明原因的宿主 modal，而不是静默隐藏这些入口。
- 在窄编辑器宽度或多运行窗口场景下，画布顶部可用空间明显大于当前“顶角 panel”方案，不再被固定大块 UI 持续占用。
- 当用户折叠、移动或暂时离开侧栏时，关键动作仍可通过命令入口完成，不会因为侧栏不可见而失去主路径。
- 在文件功能开启时，文件过滤的修改只影响文件节点 / 文件列表节点 / 自动边的显示结果，不会删改 `fileReferences`。

## 8. 开放问题

- 右下角全局定位控件第一版是否始终保留 MiniMap，还是在节点很少或编辑器极窄时允许自动收起。
- “运行中执行单元数”是否属于第一版真正需要展示的最小状态，还是只保留节点总数与 trust 状态即可。
