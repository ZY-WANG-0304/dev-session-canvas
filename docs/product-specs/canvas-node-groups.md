# 画布节点分组功能规格

## 1. 用户问题

当同一张画布上同时存在多个 `Agent`、`Terminal` 和 `Note` 时，用户可以通过连线表达关系，但仍缺少一种低成本方式把一组节点标记为同一个工作区域、阶段或子任务。节点数量上升后，用户需要靠记忆或空间摆放理解“哪些对象属于同一件事”，这会削弱画布作为多 Agent 工作台的全局可读性。

分组功能要解决的是“空间组织和批量移动”问题，而不是把 DevSessionCanvas 变成完整白板、设计工具或自动布局系统。

## 2. 目标用户

本规格优先服务在一个 VSCode workspace 内并行使用多个 `Agent` / `Terminal` 的开发者。他们通常会把多个执行节点、说明 `Note` 和关系线摆在同一张画布上，并需要按任务阶段、责任范围或上下文主题把节点收束成几个可命名区域。

## 3. 核心用户流程

1. 用户可以通过画布空白区右键菜单创建一个空分组，也可以多选两个或更多同一父级下的稳定对象后通过上下文菜单或命令面板执行“创建分组”；从选中对象创建分组至少需要 2 个对象，单个节点或单个分组不提供该入口。命令面板可以作为补充入口，节点菜单不提供创建空分组入口；首版不提供默认分组快捷键。节点多选只由按住 Ctrl / Cmd 点击节点触发，再次 Ctrl / Cmd 点击已选节点取消该节点选择；普通点击节点回退到原有单选和节点交互语义。若选中对象分属不同父分组，或同时包含某个分组及其后代对象，禁止从该选择创建分组；若选中对象包含已有子树的分组但未同时选中它的后代对象，允许创建，新分组把该分组整棵子树作为直接子分组接纳。
2. 如果从选中对象创建分组，系统根据所选对象的外接矩形创建一个带标题的分组框，并把这些对象纳入同一组；如果创建空分组，系统在用户指定位置创建可命名的空分组框；分组框采用 VSCode Panel 风格，body、标题 tab 和分组 toolbar 背景统一使用 `--vscode-panel-background`，且 body 背景位于普通节点下方，不遮盖成员节点内容；标题区域贴在分组左上角并表现为类似 Panel 顶部 tab 的标题，标题 tab 之外的顶部横向区域保持挖空透明，不绘制独立横向 header 背景条，不使用外浮胶囊；tab 与 body 边界都使用直角，body 上边界也显示边框，成员对象相对 body 左、上、右、下边界的视觉预留保持一致；分组边框在画布缩放时保持屏幕可见线宽不变；新分组默认标题使用与现有手工节点一致的创建序号递增逻辑，如 `Group 1`、`Group 2`，但分组使用独立于节点的分组序号队列；编号由分组创建序列决定，不按标题文本查找最小可用编号，删除分组后不主动复用旧编号，用户重命名不影响后续默认编号；创建时不强制弹窗命名，用户后续可单击分组标题区域进入重命名编辑；标题编辑控件先复用现有手工节点标题栏编辑方式和提交 / 取消行为；分组标题编辑清洗逻辑与现有手工节点标题一致，不设置分组专用最大长度限制，仅保留现有通用文本保护；分组标题不允许为空字符串，清空标题并确认时恢复为原标题，新建分组保持默认 `Group N`；手动重命名允许重名，不强制唯一；若新分组与同父级已有分组交叉，系统保留新分组位置并挤走同父兄弟分组。
3. 用户可以单击分组标题区域进入重命名编辑，复用现有手工节点标题栏编辑方式和提交 / 取消行为；用户也可以从上、下、左、右和四个角共 8 个方向调整分组尺寸，或把一个分组放入另一个分组中形成嵌套；resize 节点或分组时，如果鼠标移动到画布可视区域边缘，画布应保持 resize 操作并自动平移，帮助用户继续扩大或调整对象。
4. 用户拖动分组标题栏或边框时，分组、其直接成员节点和内部子分组一起移动，节点之间原有连线继续保持；移动或 resize 到画布边缘时，画面像拖动节点一样跟随鼠标自动平移；释放后的碰撞消解、父级扩容和级联收口按下方“拖动与 resize 基础法则”处理。
5. 用户可以把节点或分组拖入已有分组区域形成归属或嵌套，也可以把节点或子分组拖出当前父分组；用户还可以移动或 resize 分组。所有拖入、拖出、移动、resize、碰撞消解和自动扩容都按下方“拖动与 resize 基础法则”推导，不再为每个几何组合单独定义一套特例。
6. 用户取消分组时，成员节点和内部子分组保留在当前画布位置。
7. 用户删除非空分组时，系统弹出确认对话框，让用户选择“一并删除内部所有节点与子分组”或“仅删除当前分组并保留内部对象”；其中“一并删除内部所有节点与子分组”是危险选项，也是默认按钮。用户删除空分组时无需确认，系统直接删除该空分组。
8. Webview reload、窗口重开或扩展重启后，分组、成员关系、标题和位置恢复。

### 3.1 拖动与 resize 基础法则

后续所有拖动、拖入 / 拖出、创建后碰撞和 resize 场景都先按以下基础法则推导；若历史场景口径与法则冲突，以法则为准并回到产品讨论。

1. 合法状态法则：宿主最终持久化状态必须合法。合法状态包括分组关系是无环树 / 森林、对象最多只有一个直接父分组、同级分组不交叉、直接成员节点与直接子分组不交叉、直接子分组之间不交叉、成员归属与视觉包含一致；普通直接成员节点之间允许重叠。节点拖入分组后的节点避让策略不属于合法状态法则。
2. 意图载体法则：每次用户操作只有一个语义意图载体。拖拽的意图载体是鼠标释放位置；多选节点同时移动时，这批节点在本次移动中被理解为临时整体，所有被选节点共用主鼠标释放位置作为归属意图；resize 的意图载体是释放后的边界；从选择创建分组的意图载体是选择集合。只有意图载体能改变归属，系统修复过程产生的新几何关系不能改变归属。
3. 用户结果优先法则：先应用用户直接操作结果，例如被拖动对象的释放位置、被 resize 分组的释放边界、新建分组的位置和范围。只要不违反硬性合法状态，就不为了修复其他对象而改写这个直接结果。
4. Resize 边界意图法则：resize 真的能表达归属意图；释放后的边界既可以让不再被完整包含的直接成员节点 / 子分组移出，也可以把释放边界内完整包含的同父稳定节点 / 同父分组纳入当前分组。
5. 最小合法修复法则：应用用户意图后若状态不合法，系统只做恢复合法状态所需的最小修复。修复可以移动兄弟分组、扩展父分组、级联到外层，但不能引入新的语义意图；挤开不是固定向右平移，而是在上、下、左、右四个方向中选择能恢复合法状态且代价较小的方向。当一次修复涉及多个修复目标时，系统应把修复目标集合内部的既有几何关系作为约束：优先保持相对位置；原本有重叠关系的修复目标之间应保持重叠，原本没有重叠关系的修复目标之间不应被系统调整成重叠。
6. 子树原子法则：分组在移动和被修复时是整棵子树；拖动一个分组时，其内部节点和子分组整体跟随。计算入组目标时，候选目标必须排除被拖动分组自身及其所有后代分组，避免自包含或父子环。
7. 释放收口法则：拖动过程中只有被拖动节点或被拖动分组子树跟随鼠标移动，其他节点和分组不动；释放鼠标后，宿主基于“上一个合法状态 + 本次用户意图”一次性计算最终归属、位置、尺寸、扩容和挤走结果并回传。

## 4. 在范围内

- 首版分组对象是可见的画布分组框，服务空间组织、命名和批量移动；分组同时参与全局 fit view、初始自动 fit、动态最小缩放和 MiniMap 空间边界。
- 分组成员覆盖用户手工创建且长期稳定的 `agent`、`terminal`、`note` 节点；`file` / `file-list` 是由文件活动 owner Agent 推导归属的自动成员，用来辅助判断 Agent 之间的信息处理关系。
- 分组可以包含多种不同节点类型，也可以包含子分组；节点最多直接属于一个最小分组，分组最多直接属于一个父分组。
- 同一父分组内，直接成员节点与直接子分组之间、直接子分组与直接子分组之间不应存在交叉；直接成员节点之间允许重叠。但按当前交互设计，节点拖入分组时如果本次移入节点与目标分组内已有直接成员节点发生位置冲突，系统应优先整体平移本次移入节点簇避开已有节点；该避让策略不进入合法状态定义，其中对本次移入节点簇内部关系的保护来自最小合法修复法则对修复目标集合的通用约束。
- 所有拖动与 resize 行为以“合法状态、意图载体、用户结果优先、最小合法修复、子树原子和释放收口”为基础法则，后续新增场景优先按法则推导，而不是继续穷举特例。
- 分组框拥有标题、位置和尺寸；即使分组为空或比分组内节点更大，也应作为空间对象进入全局 fit view 和 MiniMap；默认标题使用与现有手工节点一致的创建序号递增逻辑，如 `Group 1`、`Group 2`，但分组使用独立于节点的分组序号队列；编号由分组创建序列决定，不按标题文本查找最小可用编号，删除分组后不主动复用旧编号，用户重命名不影响后续默认编号；创建时不强制弹窗命名，后续用户可以单击分组标题区域进入重命名编辑；标题编辑控件先复用现有手工节点标题栏编辑方式和提交 / 取消行为；分组标题编辑清洗逻辑与现有手工节点标题一致，不设置分组专用最大长度限制，仅保留现有通用文本保护；分组标题不允许为空字符串，清空标题并确认时恢复为原标题，新建分组保持默认 `Group N`；手动重命名允许重名，不强制唯一。允许没有任何成员。空白区创建空分组时默认尺寸为 `360 x 240`，后续用户可以调整尺寸。
- 分组 resize 提供上、下、左、右和四个角共 8 个方向；拖动左侧或上侧边界会同步改变分组位置，拖动右侧或下侧边界只改变尺寸，释放后统一按第 3.1 节基础法则收口；resize 过程中鼠标到达画布可视区域边缘时触发自动平移，自动平移只改变视口，不改变归属意图或合法状态修复语义。
- 分组移动会带动直接成员节点和内部子分组一起移动；成员节点自身仍保持原有节点交互能力。移动释放后的碰撞消解、父级扩容和级联收口按“拖动与 resize 基础法则”处理。
- 取消分组始终保留成员节点和内部子分组；删除非空分组必须先让用户选择是否一并删除内部所有节点与子分组；删除空分组无需确认。
- 分组进入宿主权威状态，并随画布持久化、恢复和 reset 生命周期同步。
- 从选中对象创建分组时，选中对象必须至少有 2 个且处于同一父级；单个节点或单个分组不提供“创建分组”，用户需要容器时应创建空分组再拖入对象；若对象分属不同父分组，或同时包含某个分组及其后代对象，禁止创建分组，避免一次创建同时跨层级移动多个对象或产生重复归属；若选中对象包含已有子树的分组但未同时选中它的后代对象，允许创建，该分组连同内部子树整体成为新分组的直接子分组。
- 创建空分组或从选中对象创建分组时，如果新分组与同父级已有分组发生交叉，保留新分组位置，并按“拖动与 resize 基础法则”消解同级交叉。
- 用户可以通过画布空白区右键菜单创建空分组，命令面板可作为补充入口，节点菜单不提供创建空分组入口；从选中对象创建分组通过上下文菜单或命令面板触发；在分组 body 空白区右键弹出的画布菜单中，新增节点、创建空分组、从选择创建分组和应用模板等新增 / 创建类操作都归属于该 body 所在分组；首版不提供默认分组快捷键；拖拽入组 / 移出、分组移动、分组 resize、系统挤走和自动扩容均按第 3.1 节基础法则计算最终归属和几何状态；删除节点或分组时，系统清理对应成员关系；删除最后一个成员后，分组框可以继续保留为空分组。
- 保存或应用模板时，若模板成员全部属于模板兼容节点集合，应保留分组结构并在应用时重新映射成员身份；`file` / `file-list` 自动文件活动节点和自动文件活动边不作为模板成员保存。
- Restricted Mode 下允许创建、移动和整理分组；它不应绕过现有执行节点创建或启动限制。

## 5. 不在范围内

- 首版支持分组嵌套，但不支持分组交叉：任意两个分组只能是互不相交或严格包含关系，不能部分重叠。
- 首版不支持折叠分组、隐藏分组内容或把分组变成代理节点摘要；后续版本也没有计划支持折叠分组。
- 首版不支持把关系线连接到分组本身；连线仍连接具体节点。
- 首版不承诺完整自动布局、泳道、网格排列或按分组自动重排节点；分组移动 / resize 的挤走只用于消解同一父分组下的局部交叉，并在上、下、左、右四个方向中选择能恢复合法状态且代价较小的方向。
- `file` / `file-list` 不能通过拖拽改到与 owner Agent 不一致的分组；用户拖动这类节点只改变位置，宿主仍按 owner Agent 重新推导 `groupId`。
- 首版不提供默认分组快捷键，也不提供跳过确认的“删除分组及其所有成员 / 子分组”快捷动作；一并删除内部对象必须通过删除分组确认对话框显式选择。
- 首版不把分组作为执行单元、任务单元、权限单元或跨 workspace 分享单元。
- 不支持给分组绑定专用说明 Note；需要说明文字时，使用普通 `Note` 节点并把它放入分组。

## 6. 关键对象与状态

### 分组

- 唯一 ID
- 标题，默认使用与现有手工节点一致的分组创建序号递增逻辑且可通过单击标题区域重命名；标题编辑控件先复用现有手工节点标题栏编辑方式和提交 / 取消行为；分组序号队列独立于节点序号队列；编辑清洗逻辑与现有手工节点标题一致，不设置分组专用最大长度限制，仅保留现有通用文本保护；不允许为空字符串；手动重命名允许重名；删除分组后不主动复用旧编号，用户重命名不影响后续默认编号
- 位置和尺寸
- 当前直接成员节点集合，可以为空
- 当前直接子分组集合，可以为空
- 可选父分组
- 选中态和拖拽态，其中选中态可以保留在 Webview 局部 UI 状态中，持久化状态只保存分组事实
- 同一父分组内，直接成员节点和直接子分组不交叉，直接子分组之间也不交叉；直接成员节点之间允许重叠；这是拖动与 resize 合法状态法则的一部分。

### 成员节点

- 节点原有身份、状态、尺寸、执行会话和 metadata 不因分组改变。
- 节点加入分组后仍可单独选择、编辑、启动、停止、调整尺寸和删除。
- 节点最多直接属于一个最小分组；当节点位于嵌套分组内时，它的直接 `groupId` 指向最内层分组，外层归属由分组父链推导。
- `file` / `file-list` 的直接 `groupId` 由 owner Agent 决定：单 owner 时跟随该 Agent 的最内层分组；多个 owner 时归属到这些 Agent 的最近公共父分组；没有公共用户分组时归到画布根，multi-root 下归到对应 `workspace-root`。如果所属 group 无法完整容纳当前 file/list 节点尺寸和位置，宿主按现有 resize-like 收口扩张 group，并带动同级避让和父级扩容；`file-list` 尺寸按当前节点尺寸处理，不额外限制用户手动放大的尺寸。
- 节点拖动入组、移出当前父分组、重新归属以及因父分组 resize 产生的成员关系变化，统一按第 3.1 节基础法则处理；宿主必须在提交前保证直接成员最终被所属分组完整容纳，且系统修正不会反向推断新的归属意图。

### 画布状态

- 分组是 workspace 绑定画布状态的一部分。
- 分组和节点使用同一套宿主持久化、恢复和 Webview 状态同步边界。
- 分组不能成为执行会话、文件活动引用或关系线事实来源。

## 7. 验收标准

- 用户可以通过画布空白区右键菜单创建空分组，也可以从画布多选至少两个同一父级下的 `agent` / `terminal` / `note` 节点或同级分组，并通过上下文菜单或命令面板创建一个分组；首版不提供默认分组快捷键；单个节点或单个分组不提供“创建分组”入口。命令面板可作为补充入口，节点菜单不提供创建空分组入口；若选中对象分属不同父分组，或同时包含某个分组及其后代对象，创建分组入口不可用或提交后被拒绝；若选中对象包含已有子树的分组但未同时选中它的后代对象，允许创建，且该分组的内部子树保持不变。
- 创建空分组后，分组框以 `360 x 240` 默认尺寸出现在用户指定位置并显示可编辑标题；从选中对象创建分组后，分组框覆盖所选对象并显示可编辑标题；分组框视觉与 VSCode Panel 保持一致，body、标题 tab 和分组 toolbar 背景统一使用 `--vscode-panel-background`，body 背景不遮盖成员节点，标题贴在左上角并以 tab 形态呈现，标题 tab 之外的顶部横向区域保持挖空透明，不显示横向 header 背景条，不使用胶囊标题；tab 与 body 边界为直角，body 上边界可见，成员对象相对 body 四边的视觉预留一致；分组边框在缩放时保持屏幕可见线宽不变；选中后显示与节点 resize 对齐的四边选中线、四角圆形控制点，以及贴在标题 tab 右侧的分组操作双段按钮；标题 tab 与双段按钮只在画板缩小时放大字体以保持清晰可见；画板放大时字体不反向缩小，视觉上跟随画板一起放大；默认按内容自然宽度显示，不主动占满分组宽度；当自然宽度达到分组宽度上限时整体不得继续变宽或超出分组框；新分组默认标题使用与现有手工节点一致的创建序号递增逻辑，如 `Group 1`、`Group 2`，但分组使用独立于节点的分组序号队列；编号由分组创建序列决定，不按标题文本查找最小可用编号，删除分组后不主动复用旧编号，用户重命名不影响后续默认编号；创建时不强制弹窗命名，用户可后续单击分组标题区域进入重命名编辑；标题编辑控件先复用现有手工节点标题栏编辑方式和提交 / 取消行为；分组标题编辑清洗逻辑与现有手工节点标题一致，不设置分组专用最大长度限制，仅保留现有通用文本保护；分组标题不允许为空字符串，清空标题并确认时恢复为原标题；手动重命名允许重名，不强制唯一；若新分组与同父级已有分组交叉，同父兄弟分组被挤走，最终状态不保留交叉。
- 用户移动分组时，其直接成员节点和内部子分组一起移动，节点内部终端或 Note 交互不被破坏；如果释放后与其他同级分组交叉，同一父分组下其他受影响的兄弟分组会被挤开，最终状态不保留交叉。
- 同一父分组内的直接成员节点与直接子分组、直接子分组与直接子分组在交互结束后的状态中不交叉。
- 同一父分组内的普通直接成员节点之间允许重叠，首版不提供通用节点间自动布局；但按当前交互设计，节点拖入分组时应对本次移入节点簇做局部避让，避免它们与目标分组内已有直接成员节点重叠。
- 用户移动单个成员节点时，不会误触发整个分组移动。
- 用户可以通过单击分组标题、边框或未被节点覆盖的 body 空白区选中分组；嵌套分组重叠区域按鼠标位置所在的最内层分组处理；双击普通分组或 workspace root section 的标题 tab 非交互空白处，或双击未被节点覆盖的 body 空白区，会把该已有分组居中 / 聚焦到当前视口，并保持分组位置、尺寸和成员关系不变；真实 pointer 双击过程中产生的未移动标题栏 drag / resize 命中必须被视为导航前置点击，不向宿主提交 `webview/moveGroup` 或 `webview/resizeGroup`；标题输入框、toolbar 按钮和 resize 控制点不会触发该聚焦动作。在分组 body 空白区右键仍打开画布上下文菜单，并把该分组作为当前选中分组；通过这个菜单触发的新增 / 创建类操作归属于该分组；在分组 body 空白区左键拖动应与画布空白区一致地平移整个画板，不移动分组本身。用户可以通过选中分组后标题 tab 右侧的双段按钮取消分组，取消后成员节点和内部子分组仍保留在当前画布位置。
- 用户可以通过双段按钮右段删除分组；删除非空分组时会看到确认对话框，并可选择一并删除内部所有节点与子分组，或仅删除分组并保留内部对象；一并删除内部对象是危险选项，也是默认按钮；删除空分组时无需确认；删除具体节点或分组时，其成员关系被清理。
- 拖入 / 拖出、分组移动和 resize 均按第 3.1 节基础法则验收：拖拽以鼠标释放位置表达归属，resize 以释放边界表达归属，用户直接结果优先保留；多选节点同时移动时，这批节点在本次移动中被理解为临时整体，所有被选节点共用主鼠标释放位置作为归属意图，其他目标的位置修复需要避开所有本次被选目标；拖动过程中其他节点和分组不动，释放后宿主一次性完成入组 / 移出 / 纳入、自动扩容和同级碰撞消解；最终状态满足合法状态法则；分组层级与成员关系在 Webview reload 和窗口重开后恢复。
- 保存并应用包含嵌套分组的模板后，新物化的节点和分组仍保留相同相对层级关系，且所有节点 ID / 分组 ID 重新生成。
- 点击全局 fit view 时，空分组和大于成员节点的分组边界也进入当前视口；右下角 MiniMap 能显示普通用户分组的空间布局，但不压过节点 attention 提示。普通 group 与 user group 是同一类非 workspace-root 分组，MiniMap 不拆分颜色 token，缩略区域的 fill 与 stroke 使用相同的主画布分组边框 token `--vscode-panel-border`，并保持足够透明度让区域可辨。
- `npm run typecheck`、Webview 分组交互回归和 VSCode reload smoke 均通过；若某项只能手动验证，应记录具体步骤、预期现象和结果。

## 8. 已确认口径

- 拖动与 resize 行为按第 3.1 节基础法则推导；如果历史场景口径与基础法则冲突，以基础法则为准并回到产品讨论。
- Resize 真的能表达归属意图；直接成员节点或直接子分组不再被释放边界完整包含时提升到父级，释放边界完整包含的同父稳定节点或同父分组可被纳入。
- 直接成员节点与直接子分组不交叉是硬不变量；同级分组不交叉、直接子分组之间不交叉、成员 / 子分组被所属分组完整容纳也都是最终合法状态要求。普通直接成员节点之间允许重叠。
- 用户结果优先；被拖动对象的释放位置、被 resize 分组的释放边界、新建分组的位置和范围优先保留，系统只做恢复合法状态所需的最小修复。
- 最小合法修复涉及多个修复目标时，应把修复目标集合内部的既有几何关系作为约束：优先保持相对位置；原本有重叠关系的修复目标之间应保持重叠关系，原本没有重叠关系的修复目标之间不应被系统调整成重叠。系统挤开同父级非法交叉时不固定向右，应在上、下、左、右四个方向中选择能恢复合法状态且代价较小的方向。
- 拖动过程中只有被拖动节点或被拖动分组子树跟随鼠标移动，其他节点和分组不动；如果拖动的是多选节点，所有被选节点作为本次直接操作目标一起跟随鼠标位移；释放鼠标后，宿主一次性处理其他分组和节点并提交最终结果。
- `file` / `file-list` 自动文件活动节点按 owner Agent 推导分组归属；用户拖动只改变位置，不改变到与 owner Agent 不一致的分组；Agent 移动到新分组后，未被抑制的自动文件节点 / 文件列表节点重新归属到新的最近公共父分组；Agent 被删除或文件活动 owner 为空后，对应自动节点消失或保持 suppression，不留下孤儿节点影响分组边界。
- 侧栏节点列表默认按分组树展示，并通过 `节点` view 标题右上角的 VSCode 原生 `...` 更多菜单提供平铺展示与按分组树展示切换；按分组树展示时，侧栏里的每个分组 section 可折叠/展开，但这只影响侧栏呈现，不代表画布分组支持折叠。
- 不支持折叠分组，后续版本也没有计划支持折叠分组。
- 新建分组默认标题使用与现有手工节点一致的创建序号递增逻辑，如 `Group 1`、`Group 2`，但分组使用独立于节点的分组序号队列；编号由分组创建序列决定，不按标题文本查找最小可用编号，删除分组后不主动复用旧编号，用户重命名不影响后续默认编号；创建时不强制弹窗命名，用户后续可单击分组标题区域进入重命名编辑；标题编辑控件先复用现有手工节点标题栏编辑方式和提交 / 取消行为；分组标题编辑清洗逻辑与现有手工节点标题一致，不设置分组专用最大长度限制，仅保留现有通用文本保护；分组标题不允许为空字符串，清空标题并确认时恢复为原标题，新建分组保持默认 `Group N`；手动重命名允许重名，不强制唯一。
- 空白区创建空分组时默认尺寸为 `360 x 240`，后续允许用户从 8 个方向 resize。
- 创建空分组主入口为画布空白区右键菜单，且该入口图标使用 `symbol-array`；命令面板作为补充入口，节点菜单不提供该入口；从选中对象创建分组通过上下文菜单或命令面板触发，右键菜单入口沿用 `group-by-ref-type`；首版不提供默认分组快捷键。
- 从选中对象创建分组时，选中对象必须至少有 2 个且处于同一父级；单个节点或单个分组不提供“创建分组”，用户需要容器时应创建空分组再拖入对象；若对象分属不同父分组，或同时包含某个分组及其后代对象，禁止创建分组；若选中对象包含已有子树的分组但未同时选中它的后代对象，允许创建，该分组连同内部子树整体成为新分组的直接子分组。
- 创建空分组或从选中对象创建分组时，如果新分组与同父级已有分组交叉，保留新分组位置，并按第 3.1 节原则消解同级交叉。
- 删除非空分组确认对话框中，“一并删除内部所有节点与子分组”是危险选项，也是默认按钮；删除空分组无需确认。
