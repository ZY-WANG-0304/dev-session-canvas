# 画布节点分组功能规格

## 1. 用户问题

当同一张画布上同时存在多个 `Agent`、`Terminal` 和 `Note` 时，用户可以通过连线表达关系，但仍缺少一种低成本方式把一组节点标记为同一个工作区域、阶段或子任务。节点数量上升后，用户需要靠记忆或空间摆放理解“哪些对象属于同一件事”，这会削弱画布作为多 Agent 工作台的全局可读性。

分组功能要解决的是“空间组织和批量移动”问题，而不是把 DevSessionCanvas 变成完整白板、设计工具或自动布局系统。

## 2. 目标用户

本规格优先服务在一个 VSCode workspace 内并行使用多个 `Agent` / `Terminal` 的开发者。他们通常会把多个执行节点、说明 `Note` 和关系线摆在同一张画布上，并需要按任务阶段、责任范围或上下文主题把节点收束成几个可命名区域。

## 3. 核心用户流程

1. 用户可以通过画布空白区右键菜单创建一个空分组，也可以多选两个或更多同一父级下的稳定对象后通过上下文菜单或命令面板执行“创建分组”；从选中对象创建分组至少需要 2 个对象，单个节点或单个分组不提供该入口。命令面板可以作为补充入口，节点菜单不提供创建空分组入口；首版不提供默认分组快捷键。若选中对象分属不同父分组，或同时包含某个分组及其后代对象，禁止从该选择创建分组；若选中对象包含已有子树的分组但未同时选中它的后代对象，允许创建，新分组把该分组整棵子树作为直接子分组接纳。
2. 如果从选中对象创建分组，系统根据所选对象的外接矩形创建一个带标题的分组框，并把这些对象纳入同一组；如果创建空分组，系统在用户指定位置创建可命名的空分组框；新分组默认标题使用与现有手工节点一致的创建序号递增逻辑，如 `Group 1`、`Group 2`，但分组使用独立于节点的分组序号队列；编号由分组创建序列决定，不按标题文本查找最小可用编号，删除分组后不主动复用旧编号，用户重命名不影响后续默认编号；创建时不强制弹窗命名，用户后续可单击分组标题区域进入重命名编辑；标题编辑控件先复用现有手工节点标题栏编辑方式和提交 / 取消行为；分组标题编辑清洗逻辑与现有手工节点标题一致，不设置分组专用最大长度限制，仅保留现有通用文本保护；分组标题不允许为空字符串，清空标题并确认时恢复为原标题，新建分组保持默认 `Group N`；手动重命名允许重名，不强制唯一；若新分组与同父级已有分组交叉，系统保留新分组位置并挤走同父兄弟分组。
3. 用户可以单击分组标题区域进入重命名编辑，复用现有手工节点标题栏编辑方式和提交 / 取消行为；用户也可以调整分组尺寸，或把一个分组放入另一个分组中形成嵌套。
4. 用户拖动分组标题栏或边框时，分组、其直接成员节点和内部子分组一起移动，节点之间原有连线继续保持；若释放后与其他同级分组形成交叉，系统保留被拖动分组的位置，并只把同一父分组下受影响的其他兄弟分组连同其内部对象挤开；挤走方向优先沿用户拖拽主方向。
5. 用户可以把节点拖入已有分组区域；只要鼠标释放位置落在目标分组框内，系统就把它加入该位置所在的唯一最内层可容纳分组，不要求被拖拽对象已经完全落在分组边界内。用户也可以把分组拖入已有分组区域形成嵌套，或通过显式动作把选中节点或分组加入已有分组 / 从分组中移出；入组后若对象未完全位于目标分组内，系统自动扩大目标分组的必要边界来容纳它；该扩容复用“只扩展越界的一侧边界、不移动目标分组原有位置，并在必要时逐层级联挤走同父兄弟分组”的规则。用户 resize 分组释放后，如果缩小边界导致直接成员节点或直接子分组不再被父分组完整包含，系统把这些对象移出当前分组并提升为当前分组父级下的同级分组；该主动 resize 移出不同于系统挤走导致的越界。用户 resize 分组释放后，如果同时存在交叉的同级分组和完整包含的同级分组，产品效果上应同时完成“消解交叉”和“纳入包含”；实现顺序上先挤走交叉的同父兄弟分组，再纳入释放时已被完整包含的同级分组，避免挤走过程或分组区域变化造成误纳入。系统挤走导致子分组超出父分组边界时，自动扩大父分组继续容纳它，不触发自动移出父分组；父分组优先只扩展越界的一侧边界，不移动父分组原有位置；若父分组扩大后与它自己的同父兄弟分组交叉，则继续按同样规则逐层向外挤走同父兄弟分组；级联到根级时，根级分组可继续被挤到无限画布上的任意位置，只需保持根级分组之间不交叉。
6. 用户取消分组时，成员节点和内部子分组保留在当前画布位置。
7. 用户删除分组时，系统弹出确认对话框，让用户选择“一并删除内部所有节点与子分组”或“仅删除当前分组并保留内部对象”；其中“一并删除内部所有节点与子分组”是危险选项，也是默认按钮。
8. Webview reload、窗口重开或扩展重启后，分组、成员关系、标题和位置恢复。

## 4. 在范围内

- 首版分组对象是可见的画布分组框，服务空间组织、命名和批量移动。
- 分组成员首版覆盖用户手工创建且长期稳定的 `agent`、`terminal`、`note` 节点。
- 分组可以包含多种不同节点类型，也可以包含子分组；节点最多直接属于一个最小分组，分组最多直接属于一个父分组。
- 同一父分组内，直接成员节点与直接子分组之间、直接子分组与直接子分组之间不应存在交叉；直接成员节点之间允许重叠。
- 分组框拥有标题、位置和尺寸；默认标题使用与现有手工节点一致的创建序号递增逻辑，如 `Group 1`、`Group 2`，但分组使用独立于节点的分组序号队列；编号由分组创建序列决定，不按标题文本查找最小可用编号，删除分组后不主动复用旧编号，用户重命名不影响后续默认编号；创建时不强制弹窗命名，后续用户可以单击分组标题区域进入重命名编辑；标题编辑控件先复用现有手工节点标题栏编辑方式和提交 / 取消行为；分组标题编辑清洗逻辑与现有手工节点标题一致，不设置分组专用最大长度限制，仅保留现有通用文本保护；分组标题不允许为空字符串，清空标题并确认时恢复为原标题，新建分组保持默认 `Group N`；手动重命名允许重名，不强制唯一。允许没有任何成员。空白区创建空分组时默认尺寸为 `360 x 240`，后续用户可以调整尺寸。
- 分组移动会带动直接成员节点和内部子分组一起移动；成员节点自身仍保持原有节点交互能力。若移动释放后形成同级分组交叉，系统只把同一父分组下其他受影响的兄弟分组挤开，而不是拒绝本次移动；挤走方向优先沿用户操作主方向，若仍无法消解交叉，再按最小位移选择水平或垂直方向。
- 取消分组始终保留成员节点和内部子分组；删除分组必须先让用户选择是否一并删除内部所有节点与子分组。
- 分组进入宿主权威状态，并随画布持久化、恢复和 reset 生命周期同步。
- 从选中对象创建分组时，选中对象必须至少有 2 个且处于同一父级；单个节点或单个分组不提供“创建分组”，用户需要容器时应创建空分组再拖入对象；若对象分属不同父分组，或同时包含某个分组及其后代对象，禁止创建分组，避免一次创建同时跨层级移动多个对象或产生重复归属；若选中对象包含已有子树的分组但未同时选中它的后代对象，允许创建，该分组连同内部子树整体成为新分组的直接子分组。
- 创建空分组或从选中对象创建分组时，如果新分组与同父级已有分组发生交叉，保留新分组并挤走同父兄弟分组；创建、移动、resize 使用一致的同级交叉消解语义。
- 用户可以通过画布空白区右键菜单创建空分组，命令面板可作为补充入口，节点菜单不提供创建空分组入口；从选中对象创建分组通过上下文菜单或命令面板触发；首版不提供默认分组快捷键；节点拖入分组区域后，只要鼠标释放位置落在目标分组框内，就按该位置加入唯一最内层可容纳分组；入组后若对象未完全位于目标分组内，系统自动扩大目标分组的必要边界来容纳它，并复用单侧扩展与级联挤走规则；节点或子分组被用户主动拖出父分组区域后自动移出父分组；主动拖出只看鼠标释放位置是否在父分组外，释放点在外即移出，即使对象矩形仍与原父分组区域部分重叠；如果释放点落在外层祖先或其他可容纳分组内，则按释放点所在的唯一最内层可容纳分组重新归属，成为该分组的直接成员 / 子分组；普通节点也遵循同一规则，释放点落在当前所属分组的外层祖先分组内时，从当前最内层分组移出并成为该祖先分组的直接成员；如果释放点不在任何分组内，则成为根级对象；分组拖入另一个分组区域后成为子分组，但分组拖动时自身内容整体跟随移动，自身及后代分组不作为本次入组目标；分组移动或 resize 造成交叉时只把同一父分组下其他受影响的兄弟分组挤开，resize 后完整包含其他同级分组时把被包含分组纳入当前分组下；resize 缩小当前分组导致直接成员节点或直接子分组不再被完整包含时，把该对象移出当前分组并提升到当前分组的父级；当交叉和完整包含同时发生时，先挤走交叉分组，再纳入释放时已被完整包含的分组；系统挤走子分组导致它超出父分组边界时，自动扩大父分组而不是移出该子分组，并优先只扩展越界的一侧边界；若父分组扩大后继续与自己的同父兄弟分组交叉，则按层级向外级联挤走同父兄弟分组；级联到根级时不受画布边界限制，只需保持根级分组之间不交叉；删除节点或分组时，系统清理对应成员关系；删除最后一个成员后，分组框可以继续保留为空分组。
- 保存或应用模板时，若模板成员全部属于模板兼容节点集合，应保留分组结构并在应用时重新映射成员身份。
- Restricted Mode 下允许创建、移动和整理分组；它不应绕过现有执行节点创建或启动限制。

## 5. 不在范围内

- 首版支持分组嵌套，但不支持分组交叉：任意两个分组只能是互不相交或严格包含关系，不能部分重叠。
- 首版不支持折叠分组、隐藏分组内容或把分组变成代理节点摘要；后续版本也没有计划支持折叠分组。
- 首版不支持把关系线连接到分组本身；连线仍连接具体节点。
- 首版不承诺完整自动布局、泳道、网格排列或按分组自动重排节点；分组移动 / resize 的挤走只用于消解同一父分组下的局部交叉，方向优先跟随用户操作主方向。
- `file` / `file-list` 自动文件活动节点暂时不支持稳定分组成员关系；这些自动节点可以在视觉上位于分组区域内，但不持久化为分组成员。
- 首版不提供默认分组快捷键，也不提供跳过确认的“删除分组及其所有成员 / 子分组”快捷动作；一并删除内部对象必须通过删除分组确认对话框显式选择。
- 首版不把分组作为执行单元、任务单元、权限单元或跨 workspace 分享单元。
- 不支持给分组绑定专用说明 Note；需要说明文字时，使用普通 `Note` 节点并把它放入分组。

## 6. 关键对象与状态

### 分组

- 唯一 ID
- 标题，默认使用与现有手工节点一致的分组创建序号递增逻辑且可通过单击标题区域重命名；标题编辑控件先复用现有手工节点标题栏编辑方式和提交 / 取消行为；分组序号队列独立于节点序号队列；编辑清洗逻辑与现有手工节点标题一致，不设置分组专用最大长度限制，仅保留现有通用文本保护；不允许为空字符串；手动重命名允许重名；删除分组后不主动复用旧编号，用户重命名不影响后续默认编号
- 位置和尺寸
- 当前直接成员节点集合，可以为空
- 当前直接子分组集合，可以为空
- 可选父分组
- 选中态和拖拽态，其中选中态可以保留在 Webview 局部 UI 状态中，持久化状态只保存分组事实
- 同一父分组内，直接成员节点和直接子分组不交叉，直接子分组之间也不交叉；直接成员节点之间允许重叠；因此用户主动 resize 父分组后被提升的直接成员节点 / 直接子分组，理论上不会与父级已有直接子分组形成新的交叉。

### 成员节点

- 节点原有身份、状态、尺寸、执行会话和 metadata 不因分组改变。
- 节点加入分组后仍可单独选择、编辑、启动、停止、调整尺寸和删除。
- 节点最多直接属于一个最小分组；当节点位于嵌套分组内时，它的直接 `groupId` 指向最内层分组，外层归属由分组父链推导。
- 节点拖入分组区域时，入组条件是鼠标释放位置落在目标分组框内，目标为该位置所在的唯一最内层可容纳分组，不要求节点矩形已完全位于分组边界内；入组后若节点或子分组未完全位于目标分组内，系统自动扩大目标分组的必要边界来容纳它，并复用单侧扩展与逐层级联挤走规则。节点被用户主动移动到父分组区域之外时，首版自动移出该父分组；主动移出按鼠标释放位置判定，释放点在父分组外即移出，即使节点矩形仍与父分组区域部分重叠。移出后若释放点落在另一个可容纳分组内，则按释放点所在的唯一最内层可容纳分组重新归属；普通节点释放点落在当前所属分组的外层祖先分组内时，也从当前最内层分组移出并成为该祖先分组的直接成员；若释放点不在任何分组内，则成为根级对象。用户主动 resize 父分组导致直接成员节点或直接子分组不再被父分组完整包含时，系统把该对象移出父分组并提升到父分组原来的父级；系统挤走导致子分组超出父分组边界时，不触发自动移出，而是自动扩大父分组继续容纳该子分组；父分组优先只扩展越界的一侧边界，不移动原有位置；若父分组因此与自己的同父兄弟分组交叉，则继续向外级联挤走同父兄弟分组；根级分组位于无限画布上，不设置画布边界限制。

### 画布状态

- 分组是 workspace 绑定画布状态的一部分。
- 分组和节点使用同一套宿主持久化、恢复和 Webview 状态同步边界。
- 分组不能成为执行会话、文件活动引用或关系线事实来源。

## 7. 验收标准

- 用户可以通过画布空白区右键菜单创建空分组，也可以从画布多选至少两个同一父级下的 `agent` / `terminal` / `note` 节点或同级分组，并通过上下文菜单或命令面板创建一个分组；首版不提供默认分组快捷键；单个节点或单个分组不提供“创建分组”入口。命令面板可作为补充入口，节点菜单不提供创建空分组入口；若选中对象分属不同父分组，或同时包含某个分组及其后代对象，创建分组入口不可用或提交后被拒绝；若选中对象包含已有子树的分组但未同时选中它的后代对象，允许创建，且该分组的内部子树保持不变。
- 创建空分组后，分组框以 `360 x 240` 默认尺寸出现在用户指定位置并显示可编辑标题；从选中对象创建分组后，分组框覆盖所选对象并显示可编辑标题；新分组默认标题使用与现有手工节点一致的创建序号递增逻辑，如 `Group 1`、`Group 2`，但分组使用独立于节点的分组序号队列；编号由分组创建序列决定，不按标题文本查找最小可用编号，删除分组后不主动复用旧编号，用户重命名不影响后续默认编号；创建时不强制弹窗命名，用户可后续单击分组标题区域进入重命名编辑；标题编辑控件先复用现有手工节点标题栏编辑方式和提交 / 取消行为；分组标题编辑清洗逻辑与现有手工节点标题一致，不设置分组专用最大长度限制，仅保留现有通用文本保护；分组标题不允许为空字符串，清空标题并确认时恢复为原标题；手动重命名允许重名，不强制唯一；若新分组与同父级已有分组交叉，同父兄弟分组被挤走，最终状态不保留交叉。
- 用户移动分组时，其直接成员节点和内部子分组一起移动，节点内部终端或 Note 交互不被破坏；如果释放后与其他同级分组交叉，同一父分组下其他受影响的兄弟分组会被挤开，最终状态不保留交叉。
- 同一父分组内的直接成员节点与直接子分组、直接子分组与直接子分组在交互结束后的状态中不交叉。
- 同一父分组内的普通直接成员节点之间允许重叠，首版不新增节点间避让或自动排布。
- 用户移动单个成员节点时，不会误触发整个分组移动。
- 用户可以取消分组，取消后成员节点和内部子分组仍保留在当前画布位置。
- 用户删除分组时会看到确认对话框，并可选择一并删除内部所有节点与子分组，或仅删除分组并保留内部对象；一并删除内部对象是危险选项，也是默认按钮；删除具体节点或分组时，其成员关系被清理。
- 用户把稳定节点拖入分组区域后，只要鼠标释放位置落在目标分组框内，该节点按鼠标释放位置加入唯一最内层可容纳分组；入组后若对象未完全位于目标分组内，目标分组会自动扩大必要边界，并复用单侧扩展与逐层级联挤走规则；用户把节点或子分组主动拖出父分组区域后自动移出父分组；主动移出只看鼠标释放位置是否在父分组外，即使对象矩形仍与原父分组区域部分重叠也移出；移出后若释放点落在外层祖先或其他可容纳分组内，则按释放点所在的唯一最内层可容纳分组重新归属，普通节点释放点落在当前所属分组的外层祖先分组内时也成为该祖先分组的直接成员；若释放点不在任何分组内则成为根级对象；用户把分组拖入另一个分组区域后形成嵌套；用户 resize 分组后，交叉状态通过挤走同一父分组下的其他兄弟分组消解，完整包含的同级分组被纳入当前分组下；如果 resize 缩小当前分组导致直接成员节点或直接子分组不再被完整包含，该对象被移出当前分组并提升到当前分组的父级；当 resize 释放后同时存在交叉和完整包含时，先挤走交叉的同父兄弟分组，再纳入释放时已被完整包含的分组；系统挤走导致子分组超出父分组边界时，父分组自动扩大且成员关系不变，并优先只扩展越界的一侧边界；若扩大后的父分组与它自己的同父兄弟分组交叉，则继续逐层消解；级联到根级时允许根级分组被挤到无限画布任意位置；分组层级与成员关系在 Webview reload 和窗口重开后恢复。
- 保存并应用包含嵌套分组的模板后，新物化的节点和分组仍保留相同相对层级关系，且所有节点 ID / 分组 ID 重新生成。

## 8. 已确认口径

- 节点或子分组被用户主动拖出父分组区域时，首版自动移出父分组；判定只看鼠标释放位置是否在父分组外，释放点在外即移出，即使对象矩形仍与原父分组区域部分重叠。移出后若释放点落在外层祖先或其他可容纳分组内，则按释放点所在的唯一最内层可容纳分组重新归属；普通节点释放点落在当前所属分组的外层祖先分组内时，也从当前最内层分组移出并成为该祖先分组的直接成员；若释放点不在任何分组内，则成为根级对象。
- 拖入位置以鼠标释放位置为准，而不是节点左上角或中心点；只要鼠标释放位置落在目标分组框内即可入组，不要求对象完全落在分组边界内。由于同级分组不允许交叉，鼠标位置最多只会落在一条嵌套链上，因此目标应是该位置所在的唯一最内层可容纳分组。
- 拖拽节点或子分组入组后，若对象未完全位于目标分组内，系统自动扩大目标分组的必要边界来容纳它，并复用“只扩展越界的一侧边界、不移动目标分组原有位置、必要时逐层级联挤走同父兄弟分组”的规则，避免出现“属于分组但视觉上在框外”的状态。
- `file` / `file-list` 自动文件活动节点暂时不支持稳定分组成员关系。
- 侧栏节点列表增加一个“更多”icon 按钮，提供按分组树折叠展示的选项。
- 不支持折叠分组，后续版本也没有计划支持折叠分组。
- 新建分组默认标题使用与现有手工节点一致的创建序号递增逻辑，如 `Group 1`、`Group 2`，但分组使用独立于节点的分组序号队列；编号由分组创建序列决定，不按标题文本查找最小可用编号，删除分组后不主动复用旧编号，用户重命名不影响后续默认编号；创建时不强制弹窗命名，用户后续可单击分组标题区域进入重命名编辑；标题编辑控件先复用现有手工节点标题栏编辑方式和提交 / 取消行为；分组标题编辑清洗逻辑与现有手工节点标题一致，不设置分组专用最大长度限制，仅保留现有通用文本保护；分组标题不允许为空字符串，清空标题并确认时恢复为原标题，新建分组保持默认 `Group N`；手动重命名允许重名，不强制唯一。
- 分组移动释放后如果与其他同级分组交叉，保留被拖动分组位置，并只把同一父分组下其他受影响的兄弟分组挤开；如果被挤走的是父分组，其内部节点和子分组整体跟随移动。
- 分组拖动时分组内容整体跟随移动，自身及后代分组不作为本次入组目标，因此不会通过拖动分组本身形成父子环。
- 分组 resize 释放后如果与其他同级分组交叉，只挤开同一父分组下其他受影响的兄弟分组；如果完整包含其他同级分组，则把被包含分组纳入当前分组下；如果缩小边界导致直接成员节点或直接子分组不再被当前分组完整包含，则把该对象移出当前分组并提升到当前分组的父级；如果交叉和完整包含同时发生，实现顺序先挤走交叉分组，再纳入释放时已被完整包含的分组。
- 同一父分组内，直接成员节点与直接子分组之间、直接子分组与直接子分组之间理论上不存在交叉；主动 resize 导致对象提升到父级时，不额外引入“移出对象与父级既有直接子分组交叉”的正常分支。
- 从选中对象创建分组时，选中对象必须至少有 2 个且处于同一父级；单个节点或单个分组不提供“创建分组”，用户需要容器时应创建空分组再拖入对象；若对象分属不同父分组，或同时包含某个分组及其后代对象，禁止创建分组；若选中对象包含已有子树的分组但未同时选中它的后代对象，允许创建，该分组连同内部子树整体成为新分组的直接子分组。
- 创建空分组或从选中对象创建分组时，如果新分组与同父级已有分组交叉，保留新分组位置，并只把同一父分组下其他受影响的兄弟分组挤开。
- 同一父分组内，普通直接成员节点之间允许重叠；该重叠不触发分组挤走、自动移出或自动排布。
- 同时碰到多个同父兄弟分组时，挤走方向优先按拖拽或 resize 的主方向决定；若仍无法消解交叉，再按最小位移选择水平或垂直方向。
- 系统挤走子分组导致它超出父分组边界时，自动扩大父分组继续容纳它；父分组优先只扩展越界的一侧边界，不移动父分组原有位置；如果扩大后与它自己的同父兄弟分组交叉，则按层级向外级联挤走，但每一层都只在同一父分组内消解；级联到根级时不设置画布边界限制，根级分组只需彼此不交叉；“拖出父分组自动移出”只适用于用户主动拖出。
