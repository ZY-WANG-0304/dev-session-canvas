# Canvas 模板功能产品规格

## 1. 用户问题

用户在使用 Canvas 时面临以下问题：

1. **首次使用门槛**：新用户打开空白画布后不知道如何开始，需要通过外部文档学习基础操作
2. **重复配置成本**：经常需要创建相似的节点组合和工作流布局，每次手动创建和连接节点效率低下
3. **工作流复用困难**：成功的多 Agent 协作配置难以保存和复用
4. **团队协作障碍**：团队成员之间缺少标准化工作流的分享机制

## 2. 目标用户

- **新用户**：首次使用插件，需要通过 canvas 本身快速了解基础操作和快捷键
- **个人开发者**：已经在 VSCode 中进行 AI 协作，希望快速启动常用的 Agent/Terminal 工作流配置
- **团队成员**：需要共享和使用标准化的多 Agent 协作模板

## 3. 核心用户流程

### 3.1 首次使用（默认模板）
1. 用户首次打开画布，或点击"重置为默认模板" / 常用操作中的"重置画板"
2. 画布自动应用当前设置的默认模板（初始为"使用说明"）
3. 用户可以在模板上直接查看基础操作说明和快捷键
4. 用户可以在此基础上继续添加节点，或清空后开始工作

### 3.2 应用其他模板
1. 打开侧边栏的模板视图
2. 浏览内置模板列表（显示节点类型统计）
3. 鼠标悬停查看详细的节点命名列表
4. 单击模板行只选中该模板，不修改画布
5. 点击行内"追加到当前画布"动作
6. 模板节点出现在视口中心（重置）或空白区域（新增），画布随后自动追焦到这组新增节点

### 3.3 切换默认模板
1. 在侧边栏模板列表中找到想要设为默认的模板
2. 点击行内"设为默认模板"动作
3. 下次重置画布或首次打开时，将使用新的默认模板

### 3.4 保存自定义模板
1. 在 Canvas 上创建和配置节点
2. 右键点击画布空白区域，选择"保存为模板"
3. 弹出接近 VSCode 原生表单风格的保存面板，而不是拆成多段 Quick Input
4. 输入模板名称
5. 选择模板保存位置（当前 workspace 或当前设备）
6. 查看当前画布中的 Agent 节点列表，并分别设置每个 Agent 在模板中的 Provider（`default` / `codex` / `claude`）
7. 提交后模板保存到所选位置中

### 3.5 分享模板
1. 在侧边栏找到要分享的模板
2. 点击"导出模板"按钮，选择保存位置
3. 或者直接从 globalStorageUri 目录复制 JSON 文件
4. 通过任何方式分享 JSON 文件（邮件、聊天、Git 等）

### 3.6 导入模板
1. 点击侧边栏的"添加模板"按钮，选择 JSON 文件
2. 打开与“保存模板”一致的表单，确认模板名称
3. 选择导入后的模板保存位置（当前 workspace 或当前设备）
4. 提交后模板出现在用户模板列表中
5. 或者直接将 JSON 文件复制到已启用的模板目录中

## 4. 在范围内

### 4.1 模板内容
- ✅ 节点位置和大小（相对位置，基准点为模板边界框左上角）
- ✅ 节点标题
- ✅ Note 节点内容
- ✅ 连线样式（颜色、箭头方向、标签）
- ✅ Agent 类型和 argv
- ✅ Agent Provider（`codex`、`claude` 或 `default`）
- ✅ 模板内部连线使用节点索引表达；不保存画布节点 id，应用模板时重新生成节点对象身份

### 4.2 Agent Provider 配置
- **Provider 类型**：
  - `default`：模板不限制 provider，应用时使用用户当前配置的默认 Provider
  - `codex`：模板要求使用 Codex provider
  - `claude`：模板要求使用 Claude provider
- **保存模板时**：由用户选择是保存为 `default`（不限制）还是保留具体 Provider（限制）
- **保存模板时**：
  - 表单应列出当前画布中的所有 Agent 节点
  - 每个 Agent 节点都可以分别选择 `default`、`codex` 或 `claude`
  - 表单可以提供“全部设为 default”或“按当前 Provider 填充”的快捷操作，但最终保存值以每个节点自己的选择为准
- **应用模板时**：
  - 如果模板使用 `default`，使用用户当前配置的默认 Provider
  - 如果模板指定了特定 Provider（如 `codex`），必须使用该 Provider
  - 如果指定的 Provider 不可用，提示用户并阻止应用模板
- **内置模板**：全部使用 `default` Provider（不限制用户的 provider 选择）

### 4.3 应用模板的位置策略
- **重置为模板**：清空画布后，将模板放置在当前视口中心
- **新增模板节点**：自动选择合适位置避免与现有节点重叠（具体算法见设计文档）
- **应用后追焦**：显式应用或重置模板后，画布视口自动 `fitView` 到本次新增的模板节点组；首次打开时的默认模板初始化仍交给初始 `fitView` 处理，不额外触发追焦

### 4.4 默认模板机制
- **初始默认模板**：首次安装时，"使用说明"模板被设为默认模板
- **默认模板标识**：在模板列表中，默认模板标题前显示文本 `(默认)`，行内"设为默认模板"动作显示填满星标；点击当前默认模板的星标不改变默认模板设置
- **切换默认模板**：用户可以将任何模板（内置或自定义）设为默认模板
- **首次打开安全回退**：如果当前默认模板因为 workspace 未受信任或执行 Provider 不可用而暂时不能应用，首次打开只临时应用"使用说明"模板，不改写用户的全局默认模板偏好
- **默认模板应用时机**：
  - 用户首次打开画布
  - 用户执行"重置为默认模板"命令
  - 用户在常用操作中点击"重置画板"
  - 用户在空白画布上执行"应用默认模板"命令

### 4.5 内置模板（2 个）

#### 4.5.1 使用说明（默认模板）
**目的**：通过 canvas 本身向新用户展示基础操作和快捷键，实现自举式教学

**内容**：
- 1-2 个 Note 节点，包含：
  - 基础操作说明（拖拽节点、缩放画布、创建连线、调整节点大小）
  - 常用快捷键列表（创建节点、删除节点、复制粘贴、撤销重做等）
  - 快速开始提示（如何创建第一个 Agent 节点）
- 可选：示例连线，展示节点之间如何建立关系

**特点**：
- 初始默认模板
- 不包含 Agent 或 Terminal 节点（避免自动启动执行会话）
- 内容简洁，聚焦核心操作

#### 4.5.2 示例模板
**目的**：为单 Agent + Terminal 的基础协作场景提供快速启动模板

**内容**：
- 1 个 Agent 节点（Provider: `default`，标题："AI Assistant"）
- 1 个 Terminal 节点（标题："Terminal"）
- 1 个 Note 节点（标题："工作说明"，内容：简短的工作流说明）
- Agent 和 Terminal 之间有连线

### 4.6 模板管理
- **命名**：只需要名称，无需描述或标签
- **同名处理**：导入时检测同名，提示用户重命名或覆盖
- **删除限制**：内置模板不可删除，只能重置为出厂状态
- **默认模板保护**：删除当前默认模板时，自动将"使用说明"设为默认模板

### 4.7 模板预览
- **主要显示**：模板名称 + 节点类型统计（不显示连线数量）
  - 示例：`示例模板 - 1 Agent, 1 Terminal, 1 Note`
- **Hover 详细信息**：显示节点命名列表
  - 示例：
    ```
    Note: "工作说明"
    Agent: "AI Assistant"
    Terminal: "Terminal"
    ```

### 4.8 存储方式
- **内置模板**：JSON 文件存储在 `resources/templates/` 目录
- **用户模板**：
  - 支持保存到 VSCode 的 `globalStorageUri/templates/`
  - 也支持保存到当前 workspace 下的 `.dev-session-canvas/templates/`
  - 支持在上述模板根目录下继续使用多级子目录组织模板
- **统一格式**：内置模板和用户模板使用相同的 JSON 格式

### 4.9 导入导出
- **导入**：
  - 提供"添加模板"按钮，让用户选择 JSON 文件，再决定导入后的名称与保存位置
  - 支持用户手动复制 JSON 文件到已启用的模板目录中
- **导出**：
  - 提供"导出模板"按钮，让用户选择保存位置
  - 支持用户手动从模板目录复制 JSON 文件

### 4.10 交互方式
- **侧边栏模板 section**：模板管理视图作为 Dev Session Canvas sidebar 容器中的 `模板` section 存在
  - 显示所有模板（内置 + workspace 用户模板 + 当前设备用户模板）
  - 视觉风格应尽量贴近 VSCode 原生 sidebar，采用紧凑列表行和分隔线，而不是厚重卡片式布局
  - 保存当前画布、导入模板、刷新列表等管理动作优先放在 view title actions 中，而不是在内容区重复放一排自定义按钮
  - 内容区只列出模板列表，不显示当前画布是否可保存之类的额外提示
  - 默认模板显示特殊标识
  - 第二行标签应精简为组合标签：内置模板显示 `内置`；市场模板显示 `市场 · 本地` 或 `市场 · 工作区`；用户保存或导入的模板显示 `自建 · 本地` 或 `自建 · 工作区`
  - 单击模板行只更新选中态，不直接应用模板到画布
  - 行内动作按钮应与模板标题保持在同一行；第二行摘要不受按钮宽度影响
  - 侧栏变窄时，模板标题和摘要逐步显示省略号，不换行撑高条目
  - 支持应用、设为默认、删除（仅用户模板）、导入、导出
  - 不需要在 sidebar 中额外显示模板目录路径
  - hover tooltip 中应补充模板来源和模板所在层级（位置 + 相对目录），帮助区分同名模板
- **右键菜单**：在画布空白区域右键
  - 根层标题区只保留"画布操作"标题，不显示额外说明文案
  - 先显示节点类型创建按钮
  - 在节点类型按钮下方用一条横线分组展示模板相关动作
  - 一级动作包含"应用模板"、"重置为模板"、"保存为模板"
  - "应用模板" 与 "重置为模板" 的一级点击都应支持对默认模板的快速操作
  - "应用模板" 与 "重置为模板" 还应支持展开二级菜单，选择具体模板
  - "重置为模板" 对所选模板执行清空后应用
- **命令面板**：通过 VSCode 命令面板快速访问
  - "Canvas: 应用默认模板"
  - "Canvas: 重置为默认模板"
  - "Canvas: 保存为模板"
- **常用操作**：侧栏 `常用操作` section 提供"重置画板"按钮，直接复用"重置为默认模板"语义，即清空当前画布后套用当前默认模板
- **保存模板对话框**：
  - 风格尽量向 VSCode 原生表单式对话面板靠拢，使用左侧标签、右侧控件和底部主次按钮
  - 输入模板名称
  - 选择保存位置（模板库根位置）
  - 列出全部 Agent 节点，并为每个节点分别选择 Provider
  - 不需要显示模板目录的绝对路径
  - 导入模板时复用同一套表单，但不显示 Agent Provider 配置区

### 4.11 错误处理
- **导入无效 JSON**：显示友好错误提示，说明 JSON 格式不正确
- **模板格式版本不兼容**：提示用户模板版本过旧或过新，无法导入
- **Provider 不可用**：
  - 如果模板指定了特定 Provider（如 `codex`）但该 Provider 不可用，提示用户并阻止应用模板
  - 提示信息应说明需要的 Provider 和如何配置
  - 不自动降级到其他 Provider，保持模板的 Provider 要求
- **同名冲突**：导入时检测到同名模板，提示用户选择重命名或覆盖
- **存储空间不足**：保存模板失败时，提示用户清理存储空间
- **模板文件损坏**：读取模板失败时，提示用户该模板已损坏，建议删除或重新导入

## 5. 不在范围内

- ❌ Agent 的 command 配置（不保存到模板）
- ❌ 运行时状态（terminal 会话、agent 状态等）
- ❌ 文件引用和文件活动边

以下能力已拆分至 `docs/product-specs/template-marketplace.md`，不在本规格范围内：

- 模板的标签或分类系统
- 模板的描述字段
- 模板的版本控制或历史记录
- 云端同步功能
- 模板市场或社区分享平台
- 模板的预览缩略图
- 模板的使用统计或推荐系统

## 6. 关键对象与状态

### 6.1 CanvasTemplate
```typescript
interface CanvasTemplate {
  id: string;                              // 唯一标识符
  name: string;                            // 模板名称
  category: 'builtin' | 'user';           // 模板分类
  nodes: CanvasTemplateNodeSnapshot[];    // 节点快照
  edges: CanvasTemplateEdgeSnapshot[];    // 连线快照
  createdAt: string;                      // 创建时间
  updatedAt: string;                      // 更新时间
}
```

### 6.2 CanvasTemplateNodeSnapshot
```typescript
interface CanvasTemplateNodeSnapshot {
  kind: CanvasNodeKind;                   // 节点类型
  title: string;                          // 节点标题
  position: CanvasNodePosition;           // 相对位置
  size: CanvasNodeFootprint;              // 节点大小
  metadata?: {
    note?: { content: string };           // Note 内容
    agent?: {                             // Agent 配置
      provider: 'codex' | 'claude' | 'default';
      argv?: string[];
    };
  };
}
```

### 6.3 CanvasTemplateEdgeSnapshot
```typescript
interface CanvasTemplateEdgeSnapshot {
  sourceNodeIndex: number;                // 源节点索引
  targetNodeIndex: number;                // 目标节点索引
  sourceAnchor: CanvasEdgeAnchor;        // 源锚点
  targetAnchor: CanvasEdgeAnchor;        // 目标锚点
  arrowMode: CanvasEdgeArrowMode;        // 箭头模式
  color?: CanvasEdgeColor;               // 颜色
  label?: string;                        // 标签
}
```

## 7. 验收标准

### 7.1 默认模板机制
- [ ] 首次打开画布时，自动应用"使用说明"默认模板
- [ ] "使用说明"模板包含基础操作说明和快捷键列表
- [ ] 用户可以将任何模板设为默认模板
- [ ] 默认模板在列表中显示特殊标识
- [ ] 执行"重置为默认模板"命令时，正确应用当前默认模板

### 7.2 基本功能
- [ ] 用户可以查看 2 个内置模板
- [ ] 用户可以应用模板到空白画布（重置）
- [ ] 用户可以应用模板到现有画布（新增）
- [ ] 用户可以保存当前画布为模板
- [ ] 用户可以删除自己创建的模板
- [ ] 内置模板不可删除
- [ ] 用户可以导入 JSON 格式的模板文件
- [ ] 用户可以导出模板为 JSON 文件

### 7.3 位置和布局
- [ ] 重置为模板时，节点出现在视口中心
- [ ] 新增模板节点时，自动避免与现有节点重叠
- [ ] 显式应用或重置模板后，画布自动追焦到本次新增的整组模板节点
- [ ] 模板内节点的相对位置关系保持一致

### 7.4 Agent Provider
- [ ] 保存模板时会列出当前画布中的 Agent 节点
- [ ] 每个 Agent 节点都可以单独选择 Provider（`default` / `codex` / `claude`）
- [ ] 应用模板时，`default` Provider 正确解析为用户当前配置的默认 Provider
- [ ] 应用模板时，指定的特定 Provider（如 `codex`）必须使用该 Provider
- [ ] 内置模板的 Agent 都使用 `default` Provider
- [ ] 指定的 Provider 不可用时，提示用户并阻止应用模板（不自动降级）

### 7.5 用户体验
- [ ] 侧边栏正确显示节点类型统计（不显示连线数量）
- [ ] 鼠标悬停时显示详细的节点命名列表
- [ ] 侧边栏组合标签能区分 `内置`、`市场 · 本地/工作区` 和 `自建 · 本地/工作区`
- [ ] 单击侧边栏模板行只选中模板，不直接应用到画布
- [ ] 模板行尾按钮与标题同一行，侧栏变窄时标题和摘要以省略号退化而不是换行
- [ ] 模板 section 内容区不显示当前画布可保存性提示，只保留模板列表
- [ ] 模板列表按创建时间排序
- [ ] 命令面板中可以快速访问模板相关命令

### 7.6 错误处理
- [ ] 导入无效 JSON 时显示友好错误提示
- [ ] 同名模板导入时提示用户重命名或覆盖
- [ ] 模板文件损坏时显示明确错误信息
- [ ] Provider 不可用时有明确提示和降级行为
- [ ] 删除默认模板时自动切换到"使用说明"模板

### 7.7 数据完整性
- [ ] 模板正确保存节点标题、位置、大小
- [ ] 模板正确保存 Note 节点内容
- [ ] 模板正确保存连线样式（颜色、箭头、标签）
- [ ] 模板不保存 Agent 的 command 配置
- [ ] 模板不保存运行时状态

## 8. 开放问题

### 8.1 已解决
- ✅ 默认模板机制：确认使用"使用说明"作为初始默认模板，用户可切换
- ✅ 同名模板处理：确认导入时提示重命名或覆盖，不允许同名共存
- ✅ Provider 配置语义：`default` 表示不限制 provider，指定特定 provider 则必须使用该 provider
- ✅ Provider 不可用处理：提示用户并阻止应用模板，不自动降级

### 8.2 待确认
- ⏳ 模板内容的具体文案：需要 UX 团队提供"使用说明"模板的具体文案内容
- ⏳ 模板列表排序规则：当前按创建时间排序，是否需要支持其他排序方式（如使用频率、字母序）
- ⏳ 模板数量限制：是否需要限制用户自定义模板的数量上限
