# 核心信念

这里记录的是协作方式上的通用信念，而不是具体方案结论。

## 1. 先写清楚问题，再开始实现

如果问题定义、目标、边界和验证方式还没有写清楚，就不应让实现细节代替设计文档。

## 2. 未确认的内容宁可留空

空白比伪确定性更安全。对未确认内容，应明确标记为“待定”“待验证”或“候选方案”。

## 3. 设计应服务于产品主张

任何技术方案都应回到核心问题：它是否真的帮助用户在多 Agent 协作中看清全局。

长期重构应维护面向原始目标的有限完成定义，而非不断累加局部阶段。已完成增量、直接产品阻塞、必要验收和可延期增强必须分账；历史证据不是当前待办，工具增强只有影响具名实验的安全或判定才阻塞它。收窄推进范围不能弱化已确认的产品完整性与真实环境验收。

产品目标和边界已清楚时，代理应承担工程取舍、预算论证和顺序判断，不把常规技术决定反复交回用户确认。已选定工程方案不等于实测通过；不能虚构数值依据，也不能借工程授权改变产品保证或削减支持范围。

持久化成功必须与正式读取路径的接受范围一致，不能保存自身生成的合法状态后，在重开时静默降级并覆盖原文件。解析之后的孤立长度检查不等于读取内存预算；通用结构校验、快照资格与整体资源约束应分别说明，不能通过任意抬高阈值或缩小验收负载掩盖读写契约不一致。

分页与容量有界不等于当前状态恢复。相同终端模型和 scrollback 的新投影恢复不应依赖已淘汰的交互历史；新读者初始化和旧读者完整消费是不同责任，不能用新状态覆盖尚未消费的尾部。

终端快照的严格校验必须覆盖固定引擎真实可产生的状态。已脱离 buffer 或暂在行尾之外的链接 marker 不代表非法输出，也不能当作有效单元格；应显式保存其生命周期语义，避免捕获时修改源端或误删未来增量仍需要的链接数据。

## 4. 计划可以推进设计，但不能替代设计

组合视图不应成为执行归属。新会话的逻辑 owner 应由明确的执行环境、用户存储范围与内容所属 root 决定；已有 live binding 是原进程的事实，不能靠改写地址迁移。共享发现还须区分启动准备、运行期排他、握手身份和本窗口订阅，不能把断连或视图消失当作无人持有。身份方案选定不等于平台来源已验证。

等待旧绑定的异步观察不能改写后来的新绑定；成功返回与失败处理都须核对等待前的完整身份，不能在等待后把当前节点重新定义为该旧观察的目标。窗口默认设置也不等于用户要求结束另一个窗口已托管的会话。

`ExecPlan` 可以用于设计阶段的探索、验证和推进，但计划本身不是设计结论。涉及问题定义、边界、候选方案和当前结论时，仍应回写正式设计文档；不要让里程碑、待办列表或实现顺序冒充架构结论。

## 5. 优先选择成熟规范的方案

验证工具应服务于当前产品风险。工具问题只有在影响本次判定或实验安全时才阻塞推进，通用健壮性不能不断扩成统一前置。预期失败或截断可以是场景通过，但验证该预期所需的证据不能缺失；局部自测数量不能替代整体执行路径和产品风险消减。

只要成熟、边界清楚、已经被广泛验证的方案能够满足目标，就不应为了局部新奇或一次性便利引入自定义机制。若决定偏离成熟方案，必须明确写清为什么成熟方案不能满足当前目标，以及偏离后的收益、代价和验证证据。

平台启动失败应以实际主体与标准流事实定位；包装器进入、进程创建成功不等于终端已正确连接。临时验收宿主的环境隔离必须显式记录，不把绕过环境依赖写成产品修复，也不由日志停止位置直接断定系统死锁。

异步操作的不同完成点必须分别确认：执行资源退役、最终状态保存、用户命令完成不能互相代替。只有原保存身份和成功结果已确认，夹具才能发起新的清理操作，且不得重置总等待预算。后续保存成功不改变已经拒绝的命令；排查应同时核对既有产品契约、实际回调链和夹具假设，不能只凭晚到成功或超时把责任归为测试。

诊断失败应分开核对产物前置、源码位置断言、真实终端几何与执行事件契约。快照参数不等于最终视口，进程实际启动也不等于某个诊断已发送；引入提交的父/子对照与单变量实验用于确认因果，不能用加宽夹具或延长等待冒充产品修复。

## 6. 文档是事实来源

如果某个结论只存在于实现细节、口头讨论或参考产品印象里，就等于它还没有被正式确认。

## 7. 平台支持必须和验证证据一起记录

原生产物的构建来源与运行要求须分开：构建宿主版本不等于最低N-API或系统库要求，兼容判断依据真实产物和供应方契约；同一字节跨宿主加载才提供装载兼容证据。编译目标、加载成功和最低OS上的完整产品行为仍是不同层级，不能互相代证或通过改写manifest追认旧产物。

真实 Agent 验收应分别记录 CLI、模型后端和执行环境：更换兼容模型服务不等于替换真实 CLI，也不以模型能力测评代替生命周期验收。专用 CI 凭据仅由显式入口交接给隔离配置，普通环境过滤保持；secret metadata、认证配置和实际模型响应是三种不同证据。远端只发布经内容扫描的固定摘要，不能为取证上传本机登录或完整 HOME；私有配置主动清理与 raw 随临时 runner 销毁是不同责任，不能混写。兼容接口或假 key 配置解析不代证联网认证；sandbox 准备失败也不能升级为 CLI/产品失败，切换兼容 runner 不应以禁用原安全边界换取通过。

清理后的退出事实不能倒推失败前主体已退出，通用等待超时不能直接定性产品根因。当前页面尾部与新 Host 恢复须分别验收；“与期望匹配”不等于“空态或原点”，报告版本变化不得重写历史事实。

异步保存或reader等待结束后，旧回调必须重新证明自己仍拥有原节点执行投影和session。失败回滚不能恢复并发变更前的整张画布、复活已清root或清理同ID replacement；只恢复仍属该次投影的执行字段，不覆盖其他root或用户布局。真实prepare入口的通过不等于完整apply或事务仲裁已通过，一个等待窗口的身份检查也不保证之后所有异步UI发布安全。

永久离开的重复观察应复用首次配置和结果，失败不能隐式开启第二轮cleanup；这与可中止的reset/reload是不同边界。锁住局部core不证明后续state replacement已串行，按root操作也不能为套用全局屏障而弱化严格删除或阻塞其他root。被撤回的候选代码及局部测试不计正式交付，未跟踪续体的源码观察须与实证失败分开。

修后单例通过不改写原矩阵失败，业务基线与实际测试提交分别追溯。退出报告、定时任务排队和实际写盘也须分账：连接已断不代表原Host状态回调已停止，实验清timer不能证明生产不会迟到覆盖。发现该直接产品风险后应沿原关闭/保存入口有限定位，不扩成通用工具或未经证明的多窗口缺陷。

业务断言失败后沿原宿主入口完成安全停止，仍是补救清理而非预定业务成功；不能只凭外层actions为空否定嵌套关闭实际发出的stop。原型实例夹具须保留所调用方法依赖的实例初始化，阈值过滤下的快速通过不证明慢路径可用；修夹具用确定性纯输入定位即可，不借此扩大工具验证或覆盖首次平台结果。

同实例模拟重载必须补齐真实重启会重建的生命周期状态。关闭后恢复准入须沿 owner 的正式约束执行，失败不能强行清标记；前置用例污染引起的超时和修后暴露的下一个失败应分别记录，不以单项修复代证完整宿主矩阵。

真实PTY与业务authority的有限验证也必须标清受控层：内存连接不等于实际client/socket，headless消费不等于Webview应用，显式删除后拒绝附着不等于Host自动收尾后的节点重开。正常退出保存不能替代运行中宿主离开；同轮原资源释放、首次结果、reader退役和清理动作分别记录，报告字段修正不覆盖原始采样或触发无必要重跑。

输入、终端尺寸变更和输出消费不可只靠共享串行队列保证一致：等待PTY可写的输入不能阻止被消费链等待的resize，否则会形成组合环等。尺寸仅在实际完成后提交authority状态，提交与新请求准入分开；结果未知时保留原责任，不把超时当作尺寸未变或完整最终态。编译、产物导入、能力声明和受控OS替身各有证明边界，均不能替代实际平台和真实Agent启动主体的验证。

已提交而结果未知的创建仍是原owner的责任，后续删除回包“不存在”不能使同节点绕过它再次启动。拒绝并发变更时也须保留原操作身份，迟到结果不应因无效的重置意图变成陌生会话；删除期间的终态广播、最终应用/保存和删除回包分别结算，轻量终态不能提前抹去失败请求的绑定或派生第二次删除。多根组合视图的破坏性操作应共用一轮边界和逐绑定结果，不把每root的局部成功合成整体成功。

从受控接线转向实际provider前，应核对完整交互和业务行为，而不只检查退出回调：初始尺寸、输入、resize、停止策略及派生状态都属于兼容面。能力选择必须发生在资源取得前，缺能力不得静默回退；旧协议的删除回包不等于新资源结算。预算候选应明确来源和未验证范围，整体观察不串接各域预算，也不把迟到连接变成截止后新发破坏性动作。

最终终端应用与最终状态保存是独立责任；磁盘失败不能倒写为消费失败，也不能因进程和reader已退役就清除尚未保存的来源。最终快照须绑定原执行及原节点身份，写入成功等待原保存Promise而非吞错的队列屏障；多个目标部分写成不等于整体成功或事务回滚。Runtime无历史与snapshot-only快照恢复的模式差异必须在真实文件读回中分别验证。

宿主整体关闭必须区分执行、reader、状态保存和连接关闭，不能用其中一个成功代替其他责任。画布快照保存只证明当次已有状态写入，不证明未投影的终端最终态落盘；宿主永久离开时本地失败不能阻止独立远端detach，本地dispose返回也不代证远端应用或OS释放。整体观察预算不取消原消费或延长原执行期限，可继续存活的owner失败时保留责任与关闭准入；Node无活跃句柄会自然退出，所需保活必须显式实现，不能仅省略exit。实际Host消失后不声称内存仍在托管。

清理权限不能从外部快照的“此刻尚未启动”推导，必须同步封闭后续启动和控制意图。资源集合为空或目前各项已释放，也不证明取得清单完整；固定provider契约应绑定原工厂并逐项核验，部分取得、额外取得和移交未知保持不准入。父控制关闭只证明父控制资源，不代证终端内容消费或页面应用。

“截止前已结算”需要原事实的结算时刻，不能在迟到timer执行时只检查当前状态。缺回执豁免仅针对效果已按时确认的操作，不扩大到provider主动未知或真实失败；观察超时不替代原消费Promise，迟到完成只补当前事实。新策略的能力门槛要贯穿owner和adapter，并由实际宿主入口验证，不能只在共享模块自测。

等待期限限定首次观察和允许动作，不生成进程退出、完整EOF或资源释放事实。绝对期限须在结果处理入口复核，不能仅由timer回调先后决定；迟到补证不改首次报告。请求受理回执与实际效果也要分开，未知责任只在仍有原owner时可继续托管，内存隔离不是宿主退出后的责任移交。

最终状态冻结应关闭新消费者准入，而不是阻止原消费者用冻结内容修复投影；取消的reader不得重开原责任。冻结前组件重新挂载可以创建新的reader，必须使用新的消费receipt身份并保留旧取消结果，不能让旧回执释放新信用。发送已完成、页面已应用和执行资源已释放必须分账；成功消费不能代替主进程状态已确认，取消消费者也不能解除未知资源隔离。并发结果要在异步等待后重验原责任，有限取消控制只保留当前在途项。

能力协商必须同时约束实际会话、传输连接和当前消费者，不能把server或页面单方支持当作整链启用。最终应用证明绑定固定终值与真实写完成；后续成功不能掩盖同一写链的前序失败，断连重试也不能把旧身份送到新连接。实际函数体/headless回调与受控内存整链互补，但不能拼成真实UI、socket或原生平台验收。

终端结果已构造、回包已提交、页面已应用是三个不同事实。逐reader登记必须覆盖准入到回包在途，不能把同socket多surface合成一个读者；没有读者或全部取消的中性结算也不能写成全部应用成功。有界幂等记录过期后只承认不可确认，不重建成功证据。接收端断言通过不能代替发送端真实写完成屏障。

真实入口验证不能由共享模块绿色代替；夹具未完成启动时，应明确保留覆盖缺口并补有界失败，不能删除该路径后宣称整链通过。测试名也不定义执行边界：启动真实Supervisor/PTY的既有回归必须与无native注入分账，发现记录分类错误时追加勘误，不追改旧结果或伪造样本数。

正常关闭责任必须落实到真实owner入口，不能把页面离开、请求受理或provider退出合并为会话已结束。准入、在途创建、内容消费、reader和资源分别结算；unknown的持续隔离需要仍存活的责任方，Host退出后的内存账本不提供控制。接入前必要能力与默认启用前异常失联风险分层处理，允许默认关闭、无native的实际接线先推进，不以此绕过真实创建安全门槛。具体落点见生产接入设计第16节。

代码路径已经接通，不等于平台支持已经完成。只要缺少对应平台的人工验证或可靠证据，就必须明确写成“验证中”或“待验证”。

跨平台实验也要验证夹具前提：创建了子进程不等于父进程退出后它仍存活，存活也不等于仍持有可写终端。平台的 Job、session leader 与终端撤销规则必须纳入对照；夹具前提失效不能冒充生产 reader 缺陷，也不能改标为产品已通过。

有界通道上的实验握手不能依赖“先写完全部内容，再开始读取”：写入可能需要消费进展才能返回，控制回执应独立于受测通道，并记录调用前后状态。前提定位与待测行为验收分别留证；修正探针不追认历史失败，失败工件也必须支持完整复核。

观察器的无侵入性必须覆盖启动链，而不只检查探针正文。继承或复制fd可能共享文件状态标志，启动库修改O_NONBLOCK会改变被观察reader；helper退出、身份/offset不变不足以排除干扰。应以原位只读观测和不传递受测资源的对照验证前提，前提失效时绿色样本也要限定结论。

控制进展不能依赖它正在等待的数据操作。写入回执、退出放行与读取循环应能独立推进，并通过暂停读取循环的受控场景验证因果顺序；一次顺利调度不构成保证。实验要求最小持有时间时应用单调截止点核对，定时器触发本身不是已经经过足够时间的证据。

底层诊断门槛与产品验收门槛要分别登记。产品职责经确认收窄时，应保留冻结实验、原断言和失败结果，显式重评是否阻塞及其理由；不修改旧测试求绿，也不把通用后代实验直接当作真实 Agent 缺陷或全平台通过证据。

取消的诚实分类不能代替完整性证明。保住已接收或在途读取的数据，仍不等于收齐系统缓冲中的尾部；诊断追加读取发现的数据必须单独计账，不能算作候选已经交付。单次资源关闭、自然进程结束也不代替长驻资源无增长验证。

资源稳定性必须在同一进程内跨多次生命周期观察，以预热基线、无资源创建对照及OS原始计数区分一次性初始化、持续积累和观测开销。能记录资源类型与身份时，不只保存总数；内容完整、JS回调收敛、驱动进程自然退出与native资源无增长分别判定。

资源归因干预必须控制重编译工具链和启动辅助程序，保留原包、重编译基线与最小干预差异。句柄槽位不是稳定对象身份，取证竞争或访问失败须显式报告；基线失败与新对照结论分别保存。

类型查询成功而对象身份查询失败时，可以分别保留已确认的类型事实与未闭合的归属问题；不能为了统一绿色而忽略查询错误，也不能把完整性通过或已退出进程对象误写成资源已释放。

Windows已退出进程被句柄引用而继续保留对象是正常语义，不等于进程仍运行或系统泄漏。缺陷判断必须另外证明调用方的资源所有权、保留用途与最终释放责任；只关闭已知owner，不能强杀或盲关陌生句柄求计数归零。

绝对截止时间不能依赖一次timer恰好按时触发：单调时钟复核未到期时需继续安排原deadline，取消必须覆盖当前timer；不得靠延长预算或把unknown改为成功掩盖丢失的首次结论。包装启动链的实际主体退出与包装器退出、观察句柄释放分别判定。

部分创建路径的子进程可能在真正执行目标程序前就以非零状态退出；`kill` 返回0只证明信号请求被内核接受，不要求随后一定以该信号结束，也不替代wait结果、owner登记或资源结算。退出形式不能单独作为资源unknown、系统缺陷或准入成功的判据。

场景符合预期、资源已结算和证据充分应分别判断；整体通过要求三者成立，继续有限诊断样本要求资源与证据均成立。内容或预期退出不符不自动抹去真实资源返回，通知与raw矛盾也不能用场景命中掩盖。判据修订使用新版本与新输入，旧失败、未运行项及入口错误保持原记录，不合并新旧通过率。

部分创建失败只结算实际取得的资源：已取得TSFN但线程未创建时，必须证明TSFN Release/finalizer和child回收；未创建的thread、payload、notification不需要虚构join、释放或回调。唯一创建者的WNOHANG返回0或EINTR仅为pending，不解释status；只有属于本child的真实终态才能证明已回收。

合成等待失败的首次未确认事实与后续真实终态必须分开保留，不能用后来成功覆盖原错误，也不能解释无效status为exit0。只有明确跳过系统调用的注入才具有随后首次真实wait的前提；真实ECHILD不因此获得重试依据。原生发布和JS观察分属不同时刻，JS晚读到首报不代表观察当时仍未退出，不为没有先观察要求的实验另增门控。

故障替身必须明确哪些真实API没有调用，以及因此仍然持有哪些资源；相同返回码不保证相同所有权状态。合成napi_closing不代表真实TSFN引用已被消耗，也不代表环境销毁；未入队payload不能交给不存在的通知回调释放。通知未交付不抹掉已确认的进程终态，预期未交付与实际资源释放失败分别判定。

资源真实释放与上层收到释放回执属于不同事实。旁路审计可以证明API已返回，但不能提前改变被测消费者的未知状态；迟到的同次操作回执只补充当前证明，不覆盖首次未知、不触发重复释放。按时与迟到必须依据各自单调截止判定，不能依赖timer回调恰好按时执行。

跨平台原生验证必须保留各平台真实创建与退出等待链。相同接口名称或成功返回不表示forkpty、posix_spawn/helper、kqueue/kevent及各类源结束语义相同；只有该平台自身的受控输入、逐资源证据和完整消费事实，才能支持其有限验收，正常已注册路径也不能外推早退或注册失败分支。

正常路径的真实read0、wait终态和单次资源释放只证明该输入的收尾，不替代失败分支的唯一reaper与逐项owner结算。macOS正常基线的10组纯测试、三次原生执行及25206项离线审计分别计数；同组复核不增加覆盖，审计范围也不能从选定旧入口保持扩大为全部历史工件深遍历。

失败注入必须先冻结数据门控和回收责任：macOS U1-6先登记kqueue owner，再合成`-1/EIO`；`registrationErrorSource=native-substitute`和`registrationCallInvoked=false`明确真实API未调用。同一driver内以实际`std::thread::id`关联唯一wait与close，不把固定角色标签冒充实测线程。ready的token/PID/TTY及gate前缀真实性属于证据核验，abort/ack身份与顺序属于资源核验；数据gate保持关闭，受控abort的exit0是场景预期；合法非零/signaled终态已回收时不虚构资源泄漏，wait未知则保留kqueue未结算并停止准入。

纯测试、构建、原生采集和离线复核分别记账。第27.10节唯一1a88d0cc/run35963751067 attempt1的macOS U1-6三次3/3及可信保存复核，不与30项纯测试或旧U1-0合算；准备期guard-only子进程和stub binary仍不是原生证据。真实取得kqueue后合成EIO、未调用注册/等待kevent的有限成功，也不证明真实系统注册错误。unknown停止准入、not-run无raw/evidence及可信离线不执行归档代码的边界不变。

生产接入不能从有限原生成功直接跳到默认启用。S3输入3f8ebcae的Linux/Node22.23.2修后唯一两场景2/2及独立原始证据核对，只关闭该固定切片的验证待办；首次0/2及18文件保持不变。正常close的源确认、主体终态、实际消费与资源结算仍分别证明，不能从本次时序外推所有调度或跨平台行为。下一阶段仅收口Linux正常关闭/卡住时的接入条件，随后推进authority接线，不把异常崩溃全矩阵或通用工具增强设为前置；其他平台、实际Agent、reader与默认启用门槛保持。

资源总量应区分显式owner引用、预热期间形成的背景和逐会话增量。普通进程控制中的退出后image31、释放23个引用后总数下降23与未知背景+5可以同时成立；保留原计数失败，不以事后换基线替代归属证据。

HPCON 是 opaque owner token，不是可用 CloseHandle 释放的普通 Win32 HANDLE。只有同一诊断模块创建并仍持有的 token，才允许在真实 pipe EOF、消费者完成和 shell 退出后由唯一主线程调用一次 ClosePseudoConsole；PtyKill、TerminateProcess、陌生句柄和过早 Close 都不能作为自然收尾。

资源因果对照还必须隔离工具本身的差异：stock 不调用候选 API，同工具链候选共享编译产物；原生等待、TSFN 和一次性连接前提失败时，不能依靠 JS 调用顺序补造成功。void 导出调用返回只证明本次调用返回，不证明 OS 已经销毁全部关联对象。

同一产物的最终释放干预消除逐会话增长，可以建立限定路径的调用方责任证据，但不自动识别每个内核对象或覆盖取消/错误路径。稳定背景差额不要求归零，故意保留 owner 的对照失败也不改绿；本轮 bundled HPCON 的原生依据见 `docs/design-docs/runtime-exit-integrity.md` 第34节。

诊断预算必须覆盖等待函数本身的返回，定时发送 kill 不等于硬截止。会话输出 EOF、driver 的 stdio 关闭、JS exit 与 OS 进程终止分别留证；工具潜在缺口与本轮是否实际触发分开判断，修订应新建版本而不覆盖冻结输入。

失败处理不能把进程事实、源完整性、消费者结果和资源安全性压成一个布尔值。资源按自身在途使用和数据移交前提回收，不因某个页面失败而永远保留native owner；也不为回收而伪造consumer完成。永久未结算的隔离与有界性必须在生产接入前解决。

首报冻结和消费者实际收到应独立核验。独立交付窗口不能改写原操作截止或把迟到首报变为及时；同样，负例被拒绝不代表原定类别已被覆盖，保存输入和具体变换须与可信fixture绑定。记录容量耗尽后的证据不可验证应明确失败，而不是以预期故障为由宣称完整归档。

归档中的生产者绝对路径是身份，不是当前机器可打开的地址。跨OS离线验证应分离逻辑路径和受约束的本地成员读取，保留链接原始字节；合成平台元数据只能验证工具规则，不能代替真实junction、权限或打包传输证据。容量条数有界不代表总字节有界，精确邻界不可达时应给出上界或步长证明，不伪造已执行覆盖。

诊断错误也是保留数据，须同时限制字段与编码后的容器大小；截断、首次省略和来源缺失应显式记录，不能只靠trace限额推断旁路有界。语义可重放与详情完整分开认证，已拒绝的错误证明不能另报完整；首报按当时前缀核验，迟到失败不能回改。局部错误预算不代表全部owner容器或进程内存有界。

unknown是当时缺少证明的观察，不应擦除已确认事实，也不阻止同一次操作的迟到补证。新证据追加，不重写首次失败、不盲重试Close、不重发已固定输出边界；旧能力释放读者仍不等于读者已应用。候选细节见 `docs/design-docs/runtime-execution-lifecycle-contract.md`。

诊断控制正确识别故障可以通过，但被测路径的超时、截断和未知仍须保留。超时后通过协作或强制控制得到的管道end不将整次采集升级为自然完整；校验器应从原始事件和单调时钟重算，而不是信任pass字段或模型自报。

调用成功不保证夹具在各平台产生相同物理效果，父端事件通知偏序也不证明两事件之间主体仍可执行。应核对固定版本底层实现并独立验证场景前提；发现绿色结果的前提缺口时保留原结果、另记未覆盖，不修改冻结脚本追认通过，也不把正常平台语义当作系统bug。

要证明资源关闭后主体仍可执行，应在观察到关闭后才生成新的私有挑战，由同一受控主体经独立通道响应；预先准备的token、PID或关闭自报都不能替代。要求持续存活窗口时，从有效响应的单调时刻计时并再次挑战，以保持资源开放和关闭后立即退出两类负控验证oracle；任何失败都不自动成为有意负控通过。补证采用新输入/工件，旧前提缺口不追认。

故障注入须同时记录载体和性质：真实进程执行native替身不等于系统调用真实失败，通知扣留不等于API卡住，有限模型不等于资源已释放。准入上限与unknown熔断限制继续积累，但不隔离共享地址空间的卡死或崩溃；每会话隔离必须在创建前安排，不能事后迁移未知owner。

返回预算的证据应来自调用方实际await续体及独立观察，不用resolve前日志代替。等待API结算、进程退出和证据落盘分别计时、分别验收；写盘失败不撤销已经确认的返回，也不能把未封存工件报告为完整证据。

独立重放必须只用当时已收到的事实推导首次报告，迟到错误不能回溯改写首报。完整owner台账和准入封禁也要从原始责任重建，不能只核最终kind。到期才冻结的超时报告不可能被消费者在原deadline前观察到；消费预算未定时应显式未闭合，不暗加宽限或伪报及时。

证据的hash自洽不等于语义可信。命令、预期、负例说明、报告与子manifest均应对齐可信输入和独立复算；标识允许分隔符时，复合key必须使用无歧义tuple编码。初轮绿色漏掉的碰撞或sidecar篡改覆盖要单独补证，不能追认历史通过已经覆盖。

## 8. 不属于空间关系的信息应优先离开画布



当某个按钮、说明或状态并不需要依赖节点位置一起理解时，应优先放到 VSCode 原生侧栏、命令入口或工具栏，而不是继续占用画布固定角落。画布应优先留给节点本体、关系和导航。

## 9. 主工作面应保留稳定回路

如果一个全局主工作面必须长期和用户的高频编辑路径争抢同一宿主区域，就不应把“切回去的成本”默认转嫁给用户。只要 VSCode 提供多个合适的宿主承载面，设计就应优先考虑让主工作面保留稳定、可预测的返回路径。

## 10. 先定义谁拥有长期运行时

如果产品要承诺“关闭画布甚至关闭 VSCode 后，会话仍继续存在”，就必须先写清楚谁拥有进程、谁负责日志、谁负责清理。不要把“快照恢复”误写成“真实进程延续”。

当同一对象能在不同窗口或组合视图中打开时，运行时归属应显式定义其运行环境、用户存储范围和稳定对象身份；创建归属与既有会话恢复绑定需要分别说明。改变新会话的归属不能自动转移旧进程所有权，必须保留旧绑定并定义退役边界。

执行会话与其内部后代的管理职责也要分开。托管 Terminal/Agent 及终端资源不自动承诺实际主进程退出后继续等待普通后代；父子关系不等于前后台关系，运行中收到的后代输出仍正常处理。启动器下的实际 Agent CLI 是执行主体，不能借后代边界排除其生命周期验证。

## 11. 第一版默认追求尽量完整实现

第一版不应默认被设计成“只证明可行”的半链路。只有在 blocker、外部依赖边界或暂不支持的平台已经被明确记录时，才允许把能力后移；否则应尽量完整实现产品主张，而不是主动把关键链路拆到后续版本。

## 12. 对象关系与文件活动优先使用结构化事件

只要某个关系或活动需要长期进入画布权威状态，就应优先使用宿主或 provider 的结构化事件，而不是从 PTY 输出、自然语言摘要或视觉文本里反推。猜测可以作为临时诊断线索，但不能冒充正式数据源。

## 13. 安装期聚合不应冒充运行时硬依赖

如果某个能力只是希望“随主产品一起安装”，但主产品在缺少该能力时仍有明确降级路径，就应把安装期聚合和运行时依赖分开表达。不要为了获得一键安装体验，把可选 companion 错写成对称的功能依赖，更不要制造会被平台判定为循环依赖的 manifest 关系。

## 14. 高频原生肌肉记忆不应被画布重写

当画布承载 VSCode 用户已经熟悉的高频原生能力时，应优先复用原生产品语义，尤其是终端里的复制、粘贴、打断、选择和焦点规则。若为了画布一致性偏离原生行为，必须先写清楚会破坏哪类肌肉记忆、为什么值得破坏，以及用户如何发现并理解这个差异。

## 15. 相似词不能复用既有语义

当一个新动作和既有动作在中文里都可叫“恢复”时，代码、协议和文档必须先区分真实对象。例如 provider session `resume` 表示用会话身份恢复历史会话；如果某个 live process 场景缺少可验证的前台恢复语义，就不能只因为 provider 文案提示“恢复”而新增同名动作。同样，恢复已有会话与重启新进程必须使用不同的可见动作语义，不能因为共用按钮组件就共用文案。不要为了文案一致性牺牲状态机边界。

## 16. 高频恢复工作不能压过交互

当系统同时需要处理用户输入、可见输出、恢复快照、诊断和派生上下文时，用户输入与当前可见输出优先；恢复、诊断、链接上下文和兼容 fallback 必须能让步、分批或静默化，除非它们正处在明确的正确性边界上。

## 17. 控制消息不能被数据洪峰淹没

当同一消息通道同时承载高频数据和交互控制信号时，控制信号应有独立的优先路径或明确的分批预算。不要假设接收端限流就足以保护 ACK、错误、生命周期和用户操作反馈。

## 18. 呈现模式不能新增事实源

当一个新交互只是为了帮助用户观察同一批对象，例如 gallery、focus、thumbnail 或其他视图模式时，它应优先作为呈现层状态，而不是新增业务事实源。若必须新增持久化状态，必须先写清它和原有事实源的同步、冲突和恢复边界。

## 19. 发布输入不能混入发布后证据

版本号、用户 release notes、Marketplace 文案和发布契约必须在发布前成为 tag 的不可变输入。工件 hash、渠道结果、workflow run 和门禁执行结果只在发布后 manifest / Release assets 中记录。不要通过修改已发布版本的 CHANGELOG 或再开 PR，把发布后事实伪装成原始发布输入。

## 20. 持久历史、终端状态与缓存需要不同边界

可靠保留恢复材料，不等于让每个进程常驻全部材料、每次投影都全量传输，或让布局保存重写历史。设计应分别说明持久数据的保留/回收、终端可恢复状态、缓存与在途传输预算；不能把数据丢弃藏在缓存上限后，也不能把分页读取等同于总恢复耗时有界。借鉴成熟系统时，先对齐其进程保活、状态恢复和历史保留承诺，再决定能否复用机制。

持久化设计先明确故障范围：客户端重建、运行时 owner 崩溃、机器重启与有序退役是不同边界。不要求跨 owner 故障恢复时，不应默认引入灾备日志或额外服务；同样，故障后的丢失许可不能被扩大成正常运行期间丢数据的许可。

单写者排他必须覆盖可能修复存储的恢复步骤，而不只是业务监听；不同启动后端共用存储时必须竞争同一归属。首次新建的启动许可不能泄漏给已有会话恢复或未知请求重放，业务 listener 关闭也不能提前释放仍需完成写盘的原 owner 责任。

已有连续增量的消费者应能独立查询新的恢复基点，不必为刷新 checkpoint 再接收同一批历史；协议优化必须保留身份和覆盖证明，且不能把传输减少误写成所有内存和恢复成本已有界。

已有可校验存储时，缓存淘汰与历史删除是不同操作。淘汰必须保留按需读取能力，读取必须验证身份、连续性和可信锚点，并阻止来源在读取中被回收；不能要求每次缓存释放都等待新的语义 checkpoint，也不能把缓存编码字节预算当作进程 RSS 保证。

分页的 wire 上限不代表读取过程的分配上限，消费信用也不能在下游仍持有未写正文时提前返还。容量优化必须保留原始字节、记录和提交校验；GC 后 retained heap、运行期采样峰值与真实交互证据分账，局部下降不能覆盖同轮预算失败。

活动会话的用户需求资源与未结算责任应分账；新建背压不等于已有会话数量硬上限，更不能在多个会话同时退出时丢弃超额责任。正式构建必须显式固定provider与匹配资产，缺资产不能静默切回另一套生命周期实现；协议声明、资产验证、实际页面消费及安装包验收仍各有证明范围。

顺序分页不应重复验证整段历史；复用已认证的有限索引时，仍须验证实际读取字节与原可信锚点，新消费者不能继承未经验证的信任。等待远端消费不应长期占用文件或阻止日志压缩，减少重复工作也不能将取消标为成功读取。

资源预算必须说明实际进程拓扑与会话负载。把多个逻辑角色放在同一进程的样本阈值，只能证明该样本是否越界，不能直接替代真实分进程、多会话的产品预算。调整其当前用途时仍保留原阈值、数值与失败，不追认为通过；真实资源和交互评估仍须完成。profiler 是具体问题的归因工具，不默认成为生产接入或其他必要验收的前置。

终端最终应用完成后，宿主自己的退出/错误提示也不能再改写主体终端内容或光标。生命周期反馈应留在终端外的已有状态或错误界面，且只属于当前执行/reader；applied 回执不能代替最终用户可见结果的检查。持久化模式同样不替代当前存活事实，snapshot-only 中仍运行的执行也应正确显示并接受操作。

分页必须贯穿实际消费者：发送一页不是消费一页，接收后重新聚合完整历史也不是有界客户端。读者的保留下界只能随实际应用推进；恢复与实时共享同一连续游标时，通知只表示可读取，不能代替内容或消费证明。

同一终端的 Host 业务消费与页面应用是独立责任，不能借用同一个 reader 身份，也不能在会话控制队列里等待远端信用。状态推送同样受容量约束；终态不能越过正文，正常退役不能先删除未消费来源，取消和迟到回执不能冒充新订阅的消费。

背压等待必须有明确的重新唤醒来源。发送排队与实际写入之间仍可能变为不可写，终态又可能是最后一次状态变化；不能依赖未来输出偶然唤醒已就绪工作，也不能用轮询或提前消费回执代替正确的drain接线。

水位提示可以只保留最新值，但接收提示、接收正文与最终应用是三个不同的完成点。提示合并不能丢失明确的状态清空，重附着不能因复用旧描述符而遗失最新水位；投递成功不自动释放接收信用，终态控制也不能被普通提示回执无限阻塞。

解析消费与恢复快照物化是不同工作。普通消费可以只等待真实解析回调和必要的存储写入，不必逐批序列化整个 scrollback；错误或取消不能返还成功信用，也不能把未刷新的缓存标为最新。最终保存、附着和 checkpoint 仍须各自取得完整且匹配序号的状态。

取消能力也要随在途责任释放。反复 race 同一个长期未决 Promise 不会自动注销失败竞争分支；已完成工作不应持续保留取消登记。释放等待不能改变真实消费完成点，销毁唤醒不能冒充成功应用，局部结构修复也不能代替整体峰值测量。

开读被取消不等于远端责任已释放。复用必须核对完整运行身份与能力，并等待同一个初始化结果；已取消但尚未取得或关闭 descriptor 的操作仍占准入，不能只统计当前绑定。超限拒绝新请求不能取消健康当前消费者，也不能把迟到或未知结算写成成功应用。

最终验收按受影响路径和同包身份收口，不按测试数量推定完备。代表性真实应用可验证共用恢复链，但不能写成其他应用已实际执行相同场景；不同时间的诊断快照与最终读盘结果也须分账。未改路径复用具名证据，历史失败和配置相关成本不因此消失，也不自动扩成下一轮工具研究。

保留范围必须由产品明确，而不是由已有存储机制反推。Runtime 已结束会话不再需要重开历史时，应取消正文归档，只保存节点与退出结果；当前页面的尾部消费与未来页面的历史恢复是不同承诺，临时收尾数据不能变成长期画板状态。故障后无需恢复也不等于可以丢运行中的未消费输出。

本地历史清理与运行中执行的删除是不同结论。历史状态标签不能证明进程已结束，旧live快照也不能证明当前仍存活；清理资格须基于原绑定的新观察、精确目标及未完责任。已有退出记录和整个Runtime已丢失是两种依据，后者须有可靠的所有者或服务停止证据，不能要求故障进程必定写下退出码才能清理，也不能冒充删除RPC成功或完整EOF，更不能借机清理共享存储中的其他会话。

历史版本曾复用同一generation却没有同样的所有权契约时，目录名不能替代版本证据；取得新锁须补排除已知无锁旧进程。临时观察锁必须实际释放才能授权，观察期限与同次未提交启动的身份有效期分别检查，不以启动新owner来证明旧owner缺席，也不让新owner反过来阻挡已完成的原绑定观察。

旧恢复过程把对象设为纯历史，不等于确认原进程退出。允许用户清理该本地对象须另有精确持久化身份、结构化恢复标记及同运行环境的新owner缺席观察；不得借兄弟记录的退出码、隔离PID视图里的空扫描或文本相似取得资格，也不得将目标级证据缓存成整个存储的许可。

终态不应自动退回全量传输。已有分页读者可以保留原来源直到消费或取消，资源回收与停止接受新读者必须分开；进程结束、节点保存、最后读者关闭和客户端退役是不同事件。跨版本协议须显式协商，不改变旧客户端仍依赖的完成契约。

事件序号连续和已交付回调排空，只能证明消费者收齐已入流的内容，不能证明生产者写出的字节全部进入了流。完整性调查应对照源、适配层与下游内容，并用实际读取终止条件验证 EOF；不能只凭 final revision 或进程退出推断源已排空。

平台抽象必须区分自然排空、强制关闭、取消与错误，不能把同名 exit/close 事件当作同等完整性保证。单个平台的实证根因不能代替其他平台的契约验证；共享源码、受控夹具和原生平台实测应分别标注，既不以未复现排除风险，也不以同源实现冒充跨平台复现。

共享原生实现时仍保留平台EOF语义和实际取得资源账本；可选创建资源不能被固定清理清单误记为必然取得。Node产品provider与匹配Electron的实际Host/Webview必须分别验收，编译或前者通过不代证后者。

源完成、消费者应用完成与资源释放也不能互相代证。协议有能力描述某种状态，不等于实际 provider 能证明该状态；诊断中的事后清理通过，不代表生产自然退出已完成资源回收。

故障隔离后的准入拒绝应保留首次底层原因，让用户能够定位磁盘等实际问题；补全错误信息不等于解除隔离或确认资源未创建。依据见 `runtime-admission-failure-details.md`。

新创建的拒绝应按原请求的明确资源结果收尾：确认没有获取执行资源且准备清理已完成时，释放该次预留并让节点可重试、可删除；不能让旧会话的隔离永久锁住被明确拒绝的新节点。结果必须绑定原身份，普通错误文案、断连、缺字段或获取后失败均不能代替证明。依据见 `runtime-admission-rejection-settlement.md`。

取消请求不能自动抹去已经拥有的数据：在途读取、解码尾片、已接受队列与页面应用需要分别结算。注入模型能证明这些屏障的顺序，但不能证明 OS 缓冲已经排空；同样，启动器等待主体的受控对照不能替代真实 provider 或其他平台的生命周期证据。

截止时的首次观察必须不可变，迟到补证追加而非改写；调用方收到结果、进程退出、真实输出结束和证据归档分别证明。完整保存失败或截断前缀不等于源完整，写入者的成功声明不等于独立校验通过；最终发布故障也不能回写已经交付的首报。

旧存储兼容应覆盖已知的原始布局与后续 generation 布局；目录代次用于识别协议范围，不应让满足同一纯历史证据的原始 workspace slot 永久依赖已缺席的 Supervisor 确认。新增布局继续逐目标核验恢复记录与当前责任，不能把未知目录或单纯断连等同于可清理。依据见 `runtime-persistence-closeout.md` 第12节第五现场。

## 执行后端迁移保留输出派生行为

终端正文送达不等于 attention 信号已处理。owned 与旧路径应复用信号解析和通知规则；提醒及用户确认属于 Host 的可信状态更新，但不得据此接管外部替换的持久化绑定。依据见 `notifier-companion-architecture.md` 第 5.3、9 节。

后端迁移也须保留成功诊断的事实来源：只有原执行确认 started，才能用该身份及实际启动参数记录成功。短命进程的启动与 cwd 验收应关联已交付快照和真实输出，不以更晚轮询时仍存活作为替代条件。源码位置断言要随职责迁移更新；终端链接测试则须按实际 cell 和折行结构验收，不能靠加宽节点隐藏混合折行缺口。依据见 `release-blockers-investigation.md`。

## 发布说明必须显式表达恢复语义的变化

用户明确接受的发布验证例外必须记录精确版本、保留检查和延后项，测试失败记录不追认为通过。0.26.0 的一次性授权见 `public-marketplace-release-readiness.md` 第 9.0 节，后续版本不自动继承。

0.26.0 将已结束持久化 Runtime 的重开收口为节点与退出状态，健康 live 会话采用类似 tmux 的重新附着，直接导入后台持有的终端当前状态，免去累计历史回放；配置内 scrollback 是当前模型的一部分。发布文案必须分别说明这两种用户结果，不能用“恢复改进”掩盖终端正文不再保留，也不能把现代系统或具名 workload 的证据扩大成旧平台、任意并发和固定资源保证。依据见 `public-marketplace-release-readiness.md` 第 9.0 节与 `runtime-live-state-recovery.md`。

请求等待超时只结束本地观察，不证明远端操作未发生。普通请求释放等待与严格删除保留迟到证据应分别定义；不能因结果未知自动重发有副作用的请求，也不能让无关输出延长请求期限。资源获取请求的调用者等待结束后，原请求仍须承担迟到 descriptor 的清理责任；该责任计入原 client 和 reader 容量，不能随 Promise 超时丢弃或转移到新连接。

测试中的阶段判断应等待该阶段的直接事实：输入回显带来的 revision 增长不证明指定输出已产生，输出后固定等待不证明退出通知已交付。受控失败与正向对照须分别记录，复跑通过不能替代同步前提修正。中间阶段的准入边界可用真实操作链上的屏障验证，不能仅等待终态后声称覆盖了收尾窗口；具体修正与反向控制见 `runtime-protocol-race-root-cause.md`。

交互就绪超时须沿实际输入、源输出和采样条件定位，不能直接等同于 RPC 超时或操作失败。一次导航后看到的选择可能在无新输入时回退；直接 PTY 及系统调用对照只证明该受控边界，不能追认原运行底层事实。setup 早退时缺少原资源基线属于清理证据缺口，不能以节点清空补成资源退出。依据见 `linux-claude-trust-startup-diagnosis.md`。

固定 CLI 验收可用经实测的幂等导航处理选择回退，但必须保留精确页面核验、导航上限、唯一确认与输入错误不重试。启动资源身份应在交互前以不可变快照持久化，完成交互后再次核对；早期身份基线不是完整 setup 成功，清理通过也不能覆盖原失败。依据见 `linux-claude-trust-startup-diagnosis.md`。
